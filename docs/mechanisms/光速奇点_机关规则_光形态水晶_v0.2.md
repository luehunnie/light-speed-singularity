## 1. 机关概述

光形态水晶是关卡固定目标对象。其最基本条件是由关卡设计者指定所需光形态：

- `RAY`：必须由光线命中；
- `PARTICLE`：必须由光粒命中。

在此基础上，同一颗水晶允许继续附加其他目标条件，例如**光线颜色要求**。当多个条件同时启用时，必须全部满足才算合法点亮。

因此它不是“只能检查一种条件”的封闭机关，而是复合条件水晶体系中的一种基础配置方式。

### 2.1 玩家道具适用性

| 项目 | 结论 |
|---|---|
| 是否允许关卡设计者预置 | ✅ |
| 是否允许进入玩家机关栏 | ❌ |
| 是否允许玩家主动放入场景 | ❌ |
| 是否允许玩家移动/回收 | ❌ |
| 推荐定位 | 仅关卡预置 |

| 最终理由 | 水晶用于固定“什么光必须到达哪里”，不能成为玩家路径工具 |

## 3. 交互规则

### 3.1 与光线交互

当所需形态为 `RAY` 时：

- RAY 满足形态条件；
- 若没有启用颜色条件，则合法命中即可点亮；
- 若启用了颜色条件，则还必须同时满足指定颜色；
- 不满足任一已启用条件时，不点亮；
- 水晶不改变 RAY 的方向或颜色。

当所需形态为 `PARTICLE` 时，RAY 不满足形态条件，因此不会点亮。

### 3.2 与光粒交互

当所需形态为 `PARTICLE` 时：

- PARTICLE 满足形态条件；
- 若没有其他适用于 PARTICLE 的附加条件，则合法命中即可点亮；
- 光粒速度默认不属于本水晶条件；
- 水晶不改变光粒方向或速度。

当所需形态为 `RAY` 时，PARTICLE 不满足形态条件，因此不会点亮。

### 3.3 与发射器的关系

本机关不直接影响发射器。判断依据始终是**到达水晶格时的真实光状态**，而不是最初发射时的状态。

### 3.5 与其他机关的交叉规则

| 场景 | 规则 |
|---|---|
| 镜面 → 水晶 | 镜面只改变方向；水晶按到达时条件判断 |
| 滤光片 → 水晶 | 若启用颜色要求，则按滤光后的实际颜色判断 |
| 光形式转换器 → 水晶 | 按转换后的实际光形态判断 |
| 加速器/减速器 → PARTICLE 水晶 | 默认不影响点亮，除非未来显式加入速度条件 |
| 光屏障 → 水晶 | 能否到达由光屏障先决定 |
| 多颗条件水晶 | 每颗独立判断；所有必需目标满足后通关 |

## 4. 边界条件

| # | 边界条件 | 行为 |
|---|---|---|
| 1 | 仅启用形态条件 | 只检查 RAY / PARTICLE 是否匹配 |
| 2 | 同时启用形态 + 颜色等多条件时（暂时作为附加） | 多项必须全部满足（暂时作为附加） |
| 3 | RAY 水晶要求红色，白色 RAY 命中 | 不点亮 |
| 4 | RAY 水晶要求红色，红色 RAY 命中 | 点亮 |
| 5 | PARTICLE 水晶同时配置颜色条件 | 非法配置；PARTICLE 不使用颜色系统 |
| 6 | 不匹配光命中 | 不点亮，但不改变该光 |
| 7 | 已点亮后再次命中 | 保持点亮 |
| 8 | 到达前发生形态转换 | 按到达时形态判断 |
| 9 | 到达前发生滤色 | 按到达时颜色判断 |
| 10 | R 重置 | 恢复未点亮 |

## 6. 重置规则（R）

| 步骤 | 行为 |
|---|---|
| 1 | 使当前光执行失效 |
| 2 | 清理动态光路/光粒 |
| 3 | 将水晶恢复为未点亮 |
| 4 | 保留全部关卡配置条件 |
| 5 | 重置对应目标完成状态 |
| 6 | 返回 SETUP |

| 涉及系统 | 本机关与它的关系 |

| 视觉表现 | 必须表达当前启用的关键条件与点亮状态 |

## 8. 复合条件规则详情

### 8.1 条件组合原则

所有“已启用”的条件之间使用 **AND（并且）**。

例如：

```text
required_form = RAY
required_color = RED
```

只有：

```text
RAY 且 RED
```

同时成立时才点亮。

### 8.2 形态与颜色组合

| 所需形态 | 颜色条件 | 合法性 | 点亮条件 |
|---|---|---:|---|
| RAY | 无 | ✅ | 任意颜色 RAY |
| RAY | RED | ✅ | 红色 RAY |
| RAY | GREEN | ✅ | 绿色 RAY |
| RAY | BLUE | ✅ | 蓝色 RAY |
| PARTICLE | 无 | ✅ | 任意速度 PARTICLE |
| PARTICLE | RED/GREEN/BLUE | ❌ | 非法关卡配置 |

### 8.3 未来附加条件扩展

同一水晶未来可以继续附加：

- 组 ID；
- 顺序编号；
- 完成窗口；
- 其他明确设计的目标条件。

新增条件仍遵循“启用条件全部满足”的原则，但每一种新增条件都必须有自己的正式规则文档或公共目标规则。

## 9. 测试用例

### 用例 1：纯形态条件

| # | 配置 | 输入 | 预期 |
|---|---|---|---|
| 1.1 | RAY | RAY | 点亮 |
| 1.2 | RAY | PARTICLE | 不点亮 |
| 1.3 | PARTICLE | PARTICLE | 点亮 |
| 1.4 | PARTICLE | RAY | 不点亮 |

### 用例 2：形态 + 颜色

| # | 配置 | 输入 | 预期 |
|---|---|---|---|
| 2.1 | RAY + RED | 红色 RAY | 点亮 |
| 2.2 | RAY + RED | 白色 RAY | 不点亮 |
| 2.3 | RAY + RED | 红色以外 RAY | 不点亮 |
| 2.4 | RAY + RED | PARTICLE | 不点亮 |

### 用例 3：非法组合

| # | 配置 | 预期 |
|---|---|---|
| 3.1 | PARTICLE + RED | LevelValidator 报告非法 |
| 3.2 | PARTICLE + BLUE | LevelValidator 报告非法 |

### 用例 4：保持与重置

| # | 前置条件 | 操作 | 预期 |
|---|---|---|---|
| 4.1 | 已合法点亮 | 光离开/消失 | 保持点亮 |
| 4.2 | 已点亮 | 后续不匹配光再次命中 | 仍保持点亮 |
| 4.3 | 已点亮 | 按 R | 恢复未点亮 |

## 10. 视觉说明

| 项目 | 说明 |
|---|---|
| 视觉资源 | 图片通过外部配置文件管理 |
| 形态条件 | RAY / PARTICLE 目标必须有明显区分 |
| 颜色条件 | 启用颜色要求时，应额外表现对应颜色条件 |
| 多条件显示 | 应让玩家能理解“这是同时要求形态 + 颜色”，避免只显示其中一项 |
| 点亮状态 | 未点亮 / 已点亮必须明显区分 |
| 玩家拖拽预览 | 不适用 |
| 缺失回退 | 显示形态/颜色文字或图标占位，不崩溃 |
