# 《光速奇点》机关规则：主发射器

> 版本：v0.3
> 日期：2026-08-13
> 作者：陈俊贤
> 优先级：P0（9月5日前必做）
> 适用光形态：光线 ⏳ | 光粒 ⏳
>
> v0.3 修订：
> - 冻结编辑器/模板默认朝向为 RIGHT（向右）；
> - 每个具体关卡的初始朝向仍由关卡设计者决定；
> - 冻结 `W` 为八方向顺时针循环切换；
> - 冻结 `Q` 为 RAY / PARTICLE 光形态切换；
> - `Space` 发射、`R` 完整重置保持不变；
> - 删除此前“方向/形态具体输入方式再议”的候选方案表述。
>
> v0.3 追加（M4-E1 多发射 Runtime 基础冻结）：
> - 光形态切换时机放宽：只要关卡 `allow_form_switch=true`，`SETUP` / `READY_TO_FIRE` / `PULSE_ACTIVE` / `MOVE_WINDOW` 均允许 `RAY↔PARTICLE`；仅 `COMPLETED` 禁止；
> - 形态切换只影响“后续发射”，场上已存在的 Ray / Particle 不受影响；
> - 主发射器发射间隔冻结为固定 **0.5 秒 cooldown**（RAY / PARTICLE 共用同一 cooldown）；
> - 不再要求“场上没有光才能再次发射”——场上活动 emission 不阻止再次发射；
> - 同一 Runtime（同一 generation / runtime epoch）内允许并存多个 emission；
> - 只有“成功发射”才开始新的 0.5 秒 cooldown；失败 / 拒绝发射、形态切换均不消费 / 不重置 cooldown；
> - `READY_TO_FIRE` / `PULSE_ACTIVE` / `MOVE_WINDOW` 最终均支持“cooldown ready → 可再次发射”；`SETUP` / `COMPLETED` 仍不可发射。
>
> v0.3 追加（M4-E2.1 per-emission 生命周期阻断项收口冻结）：
> - 每次成功发射都是**独立 emission**（独立 emission_id、独立生命周期）；
> - 光未消失时，**0.5 秒 cooldown 到期后仍允许再次发射**（活动光不阻止再次发射，唯一节流为 cooldown + 发射权限）；
> - **RAY + RAY 可共存**；**PARTICLE + PARTICLE 可共存**；**RAY + PARTICLE / PARTICLE + RAY 可共存**（同一 Runtime 内多 emission 并存）；
> - 每个 emission 有**独立生命周期**：单个 emission 的完成 / 清理**不得影响**其它 active emission（per-emission ownership）；
> - dispatch 失败（未知形态 / Ray 构造失败 / 光粒发射失败）只回滚**本次 emission**，不留活动 zombie，不影响已存在 emission；
> - RAY / PARTICLE **共用同一 0.5 秒 cooldown**（形态无关、形态切换不重置）；
> - `Q` 只影响**后续发射**——不改变场上已存在的 emission、不重置 / 不消费 cooldown；
> - `Q` 的正式输入、`PULSE_ACTIVE` 玩家连续 Fire 入口、cooldown 作为发射硬门在 E2.1 时点**尚未实现 / 未开放**（M4-F1 注：三项已于 M4-E3/E4 全部实装，见下方实装状态说明）。
>
> 实装状态说明（M4-E4 后，M4-F1 同步）：
> - 已实装：generation epoch 语义、单调 emission_id、`ActiveEmissionRegistry`（含 runtime_id 双向映射 + bind/rebind 原子一致性）、0.5 秒 cooldown 组件（M4-E3 起为 `request_fire` 硬门：成功消费一次，失败 / 拒绝 / 形态切换不消费）、`ParticleScheduler` 同 generation 多光粒、Tick 泵单链 + stale-drained 重入修复、Visual 同 generation 多 EMITTED 共存、`RayEmissionDriver`（immutable snapshot + per-emission visual delay + 独立 completion）、per-emission 聚合结算（`_finish_emission`）、dispatch 显式成功/失败 transaction（失败 rollback 不留 zombie）、joined failure 不影响旧 emission、`PULSE_ACTIVE` repeated fire（M4-E3，玩家 Space 连发入口已开放）、`Q` 正式输入接线（M4-E4：`request_switch_light_form` 权限门 + 形态切换提示；R 恢复关卡初始形态）、Ray 多发 per-emission 视觉 ownership（新 Ray 不清旧 Ray，单 emission 结束只清自身视觉）、RAY/PARTICLE 同代混合视觉并存。
> - **尚未实现 / 未开放（不得在当前实现状态中写成已完成）**：GUI 人工验收（多发射连发、Q 四允许状态、混合形态无残影等，留 M4-F2 Human Acceptance）；API 目标件（`fixed_emitter.tscn` 独立预制、统一 `EmissionRequest`、`validate_emitter`，见接口设计文档 §15）。
> - 本版规则为冻结目标；当前 Test 已白盒覆盖 per-emission 并发 / dispatch failure / joined failure / 四 emission 混合 / reset 旧 timer 等契约，M4-E3/E4 起玩家路径（repeated fire 0.499/0.500 cooldown 边界、Q 权限与切换语义）亦已含自动化测试。

## 1. 机关概述

主发射器是每关的固定核心发射对象。

它由关卡设计者预置在关卡中，玩家不能移动、回收或重新放置主发射器。

在 `SETUP` 阶段：

- 玩家可以调整主发射器朝向；
- 玩家按 `W` 时，主发射器沿固定顺时针顺序切换到下一个方向；
- 若本关允许切换光形态，玩家可按 `Q` 在 `RAY` / `PARTICLE` 之间切换。

点击“开始运行”后：

- 当前方向锁定；
- 当前初始光形态锁定；
- `W` 与 `Q` 不再改变主发射器配置。

运行阶段：

- `Space` 发射；
- `R` 执行完整关卡重置。

PARTICLE 从主发射器发射时，默认以**标准速度**开始传播。

## 3. 朝向规则

### 3.1 八方向

主发射器的 RAY 与 PARTICLE 共用八方向：

| 顺序 | 方向 | 向量 |
|---:|---|---|
| 0 | RIGHT | `(1,0)` |
| 1 | DOWN_RIGHT | `(1,1)` |
| 2 | DOWN | `(0,1)` |
| 3 | DOWN_LEFT | `(-1,1)` |
| 4 | LEFT | `(-1,0)` |
| 5 | UP_LEFT | `(-1,-1)` |
| 6 | UP | `(0,-1)` |
| 7 | UP_RIGHT | `(1,-1)` |

该表同时定义 `W` 的**顺时针循环顺序**。

### 3.2 W 顺时针切换

在 `SETUP` 中，每按一次 `W`：

```text
RIGHT
→ DOWN_RIGHT
→ DOWN
→ DOWN_LEFT
→ LEFT
→ UP_LEFT
→ UP
→ UP_RIGHT
→ RIGHT
→ ...
```

规则：

- 每次只前进一个 45° 朝向；
- 到 `UP_RIGHT` 后再次按 `W` 回到 `RIGHT`；
- 不存在越界方向；
- 开始运行后 `W` 无效；
- 当前版本不额外定义“逆时针切换”按键。

### 3.3 默认朝向与关卡初始朝向

必须区分两个概念：

**编辑器/模板默认值：**

```text
RIGHT
```

含义：

- 新建主发射器对象；
- 未由关卡设计者修改朝向时；
- 默认显示为向右。

**具体关卡初始朝向：**

- 由关卡设计者在制作该关卡时决定；
- 可以是八方向中的任意一个；
- 玩家进入关卡后，以关卡保存的初始朝向为起点；
- `R` 重置时恢复到该关卡自己的初始朝向，而不是强制恢复为 RIGHT。

示例：

```text
模板默认 RIGHT
↓
关卡设计者把某关配置为 UP_LEFT
↓
玩家进入该关：初始为 UP_LEFT
↓
玩家按 W：切到 UP
↓
按 R：恢复 UP_LEFT
```

## 4. 光形态切换规则

### 4.1 Q 按键

`Q` 正式冻结为主发射器初始光形态切换键。

若本关允许形态切换：

```text
RAY ↔ PARTICLE
```

每按一次 `Q` 切换一次。

若本关禁止形态切换：

- `Q` 不改变主发射器当前光形态；
- 保持关卡设计者指定的初始形态。

### 4.2 切换时机

只要本关允许形态切换（`allow_form_switch=true`），除 `COMPLETED` 外的运行状态均允许切换：

| 状态 | Q 是否允许（关卡允许形态切换时） |
|---|---:|
| SETUP | ✅ |
| READY_TO_FIRE | ✅ |
| PULSE_ACTIVE | ✅ |
| MOVE_WINDOW | ✅ |
| COMPLETED | ❌ |

若本关禁止形态切换（`allow_form_switch=false`），任何状态下 `Q` 都不改变主发射器当前光形态，保持关卡设计者指定的初始形态。

切换语义（v0.3 冻结）：

- 形态切换**只影响后续发射**——场上已存在的 Ray / Particle 继续按其原形态传播，不受切换影响；
- 形态切换**不重置**发射 cooldown，也**不消费** cooldown；
- 切换不立即发射，下一次 `Space`（通过 cooldown 与发射权限校验后）才以新形态发射；
- `COMPLETED` 冻结全部交互，故禁止切换。

## 5. 发射规则

### 5.0 发射 cooldown（v0.3 冻结）

主发射器有统一的 **0.5 秒发射 cooldown**：

- `FIRE_INTERVAL_SECONDS = 0.5`；
- RAY / PARTICLE **共用同一 cooldown**（不区分形态）；
- 只有**成功发射**才开始新的 0.5 秒 cooldown；
- 失败 / 被拒绝的发射**不消费** cooldown；
- 形态切换**不重置** cooldown；
- `R` 完整重置后 cooldown 恢复 ready；
- cooldown 与场上活动 emission 数量**完全独立**——不依赖 Particle / Ray / active emission 计数。

`READY_TO_FIRE` / `PULSE_ACTIVE` / `MOVE_WINDOW` 最终均支持“cooldown ready → 可再次发射”；`SETUP` / `COMPLETED` 仍不可发射。

### 5.1 活动光不阻止再次发射

v0.3 起**不再要求**“场上没有光才能再次发射”：

- 场上已存在的 Ray / Particle 不阻止主发射器再次发射；
- 唯一的发射节流为 §5.0 的 0.5 秒 cooldown（与发射权限状态）；
- 同一 Runtime（同一 generation / runtime epoch）内允许并存多个 emission。

### 5.2 RAY

当前形态为 RAY 时：

1. 玩家按 `Space`；
2. 通过发射权限（非 SETUP / COMPLETED）与 0.5 秒 cooldown 校验；
3. 读取主发射器当前格；
4. 读取当前八方向朝向；
5. 创建 RAY 发射，分配唯一 `emission_id`，开始新的 0.5 秒 cooldown；
6. 后续传播由 RAY 系统处理。

### 5.3 PARTICLE

当前形态为 PARTICLE 时：

1. 玩家按 `Space`；
2. 通过发射权限（非 SETUP / COMPLETED）与 0.5 秒 cooldown 校验；
3. 读取主发射器当前格；
4. 读取当前八方向朝向；
5. 创建 PARTICLE，分配唯一 `emission_id`，开始新的 0.5 秒 cooldown；
6. 初始速度固定为**标准**；
7. 后续按光粒八方向与整数 Tick 规则传播。

## 6. 默认按键（冻结）

| 功能 | 按键 | 规则 |
|---|---|---|
| 顺时针切换八方向 | `W` | SETUP 中每按一次顺时针 +45° |
| 切换 RAY / PARTICLE | `Q` | 仅关卡允许且非 COMPLETED 时有效；只影响后续发射 |
| 发射 | `Space` | 受发射权限（非 SETUP / COMPLETED）与 0.5 秒 cooldown 共同约束；活动光不阻止再次发射 |
| 完整重置 | `R` | 恢复完整关卡初始状态；cooldown 恢复 ready |

当前不再采用：

- WASD 组合直接指定八方向；
- 方向键组合直接指定八方向；
- 鼠标八方向选择作为当前正式方案。

若未来需要新增替代输入，可作为辅助输入另行讨论，但不得改变本版冻结的默认操作。

## 7. 玩家操作权限

| 操作 | SETUP | READY_TO_FIRE ⏳ | PULSE_ACTIVE | MOVE_WINDOW | COMPLETED |
|---|---|---|---|---|---|
| W 顺时针调向 | ✅ | ❌ | ❌ | ❌ | ❌ |
| Q 切换形态（关卡允许时） | ✅ | ✅ | ✅ | ✅ | ❌ |
| Space 发射 | ❌ | ✅ | ✅（cooldown ready 且发射权限允许时可再次发射；M4-E3 已开放 repeated fire） | ✅ | ❌ |
| 移动发射器 | ❌ | ❌ | ❌ | ❌ | ❌ |
| 回收发射器 | ❌ | ❌ | ❌ | ❌ | ❌ |
| R 完整重置 | ✅ | ✅ | ✅ | ✅ | ✅ |

> 说明：`Q` 切换只影响后续发射，不重置 / 不消费 cooldown，且**不改变场上已存在的 emission**。`Space` 在 `PULSE_ACTIVE` 的**玩家连续 Fire 入口已于 M4-E3 开放**；cooldown 作为 `request_fire` 硬门同样已于 M4-E3 实装（成功消费一次、拒绝不消费）。本版冻结的“活动光不阻止再次发射”“0.5 秒 cooldown”“同 Runtime 多 emission 并存”“per-emission 独立生命周期”已自 M4-E2.1 起在 Runtime/Registry/Driver 层白盒兑现并测试，M4-E3/E4 补齐玩家路径（repeated fire / Q）自动化测试。

## 8. 配置锁定规则

| 配置项 | SETUP | 开始运行后 |
|---|---:|---:|
| 主发射器方向 | 可用 W 修改 | 锁定 |
| 主发射器初始光形态（开始运行时的起点） | 关卡允许时可用 Q 修改 | 锁定（作为该 Runtime 的初始形态） |
| 主发射器当前光形态 | 关卡允许时可用 Q 修改 | 关卡允许且非 COMPLETED 时可用 Q 修改（只影响后续发射） |
| 主发射器位置 | 玩家始终不可修改 | 玩家始终不可修改 |
| PARTICLE 初始速度 | 固定标准 | 固定标准 |

开始运行后锁定的只是“方向”与“该 Runtime 的初始形态起点”；当前光形态在非 COMPLETED 状态下仍可由 `Q` 切换（受 `allow_form_switch` 约束），切换只影响后续发射，场上已存在的 emission 不受影响。

传播过程中：

- 镜面仍可改变方向；
- 加速器/减速器仍可改变光粒速度；
- 后续形态转换器仍可改变传播中的光形态。

这些都不会反向修改主发射器配置。

## 9. 重置规则（R）

R 是完整关卡重置。

对主发射器：

1. 清理当前 RAY / PARTICLE；
2. 恢复**该关卡配置的初始朝向**；
3. 恢复该关卡配置的初始光形态；
4. PARTICLE 下一次发射仍从标准速度开始；
5. 回到 SETUP；
6. 若关卡允许，玩家可重新用 `W` 调向、用 `Q` 切换形态；
7. 重新要求点击“开始运行”。

> R 不会把所有关卡都强制恢复为 RIGHT。RIGHT 只是新建发射器时的默认配置值。

## 10. 与其他系统的交互边界

| 涉及系统 | 本机关与它的关系 |
|---|---|
| 关卡编辑 | 模板默认 RIGHT；关卡设计者可保存任意八方向作为关卡初始朝向 |

| PARTICLE 系统 | 提供起点、方向、标准初始速度 |
| 库存 | 不进入玩家库存 |
| 场上占用 | 固定占用一格 |
| 视觉表现 | 当前朝向与当前光形态必须实时可辨 |

| 14 | 成功发射后 0.499 秒按 Space | cooldown 未到，不发射（不消费新 cooldown） |
| 15 | 成功发射后 0.500 秒按 Space（发射权限允许时） | cooldown ready，允许再次发射，开始新的 0.5 秒 cooldown |
| 16 | 场上仍有未结束 emission 时按 Space（cooldown ready 且发射权限允许时） | 允许再次发射，新旧 emission 并存于同一 Runtime |
