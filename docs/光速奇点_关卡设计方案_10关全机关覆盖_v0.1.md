### 1.3 难度曲线

- 每章第 1 关为教学关：单概念、解法唯一或接近唯一、库存富余、失败反馈即时。
- 每章末关为综合关：多机关组合、多目标、存在干扰项，但解法链路唯一。
- 光粒章与混合章的监测器触发纳入通关条件（设计决策 D-1，见 §8）。

### 1.4 与既有《2教学+2综合》方案的关系

本方案是覆盖全部机关的完整 10 关战役提案，与既有 4 关方案存在概念重叠：既有教学关 2"转向"≈ R1，既有综合关 1"反射长廊"≈ R4 的镜面链路思路，既有综合关 2"双形态"≈ M1。若两套方案并存，建议以本方案为战役主干，既有教学关 1"第一束光"（即已实装的 `level_ray_001`）保留为光线章第 0 关（发射器瞄准教学），本方案 R1 顺延为第 1 关。

## 2. 全局约定

### 2.1 坐标与像素

- 格坐标 `(x, y)`，左上角为原点，x 向右、y 向下。
- 1 格 = 64×64 像素；格中心像素 = `(32 + 64x, 32 + 64y)`。
- 文中所有布置均按格坐标描述，落地时在 Godot 中用 64px 网格吸附。

### 2.2 地图图例

| 符号 | 含义 |
|---|---|
| `E>` `E↘` 等 | 主发射器，箭头为初始发射方向 |
| `#` | 墙体 |
| `c` | 基础水晶 |
| `R` `G` `B` | 光颜色水晶（红/绿/蓝） |
| `L` | 光线形态水晶 |
| `P` | 光粒形态水晶 |
| `F` | 滤光片（颜色与薄膜朝向见配置表） |
| `B` | 光屏障（穿越轴见配置表） |
| `S` | 光粒速度监测器（轴与目标档位见配置表） |
| `T` | 光形式转换器 |
| `.` | 空白可放置格 |

玩家库存机关不出现在地图上，见各关配置表；预期解中的玩家放置位置以坐标给出。

### 2.3 速度档位速查（正交方向）

| 档位 | 每格 Tick | 秒 |
|---|---|---|
| 慢速 | 8 | 0.8s |
| 标准 | 4 | 0.4s |
| 快速 | 2 | 0.2s |

发射器光粒初始 = 标准。加速器方向匹配 +1 档，减速器方向匹配 −1 档，屏障轴向通过后 −1 档（慢速撞屏障停止）。斜向速度本方案未使用（全部解法路径为正交方向）。

### 2.4 通关条件约定

- 默认：全部水晶点亮。
- 含监测器的关卡（P1、P3、M3）：全部水晶点亮 **且** 全部监测器成功触发（监测器触发事件接为目标事件，见设计决策 D-1）。

### 2.5 通用机关落地约定

- 滤光片按 v0.1 文档现状为**关卡预置**（不进机关栏）。
- 光屏障、速度监测器、光形式转换器为关卡预置。
- 所有光屏障两侧按规则配护墙。
- 光线章（R1–R4）发射器 `allow_form_switch = false`；混合章（M1–M3）`allow_form_switch = true`，初始形态 RAY。

1. 将斜面镜放置于 (7,3)，保持 `/` 朝向。

- TOP 朝向放在同位置属于背面命中，停止；作为错误尝试的反馈。
- 本关同时教学"斜向光"概念，为双格镜的端点穿越规则（后续扩展关）铺垫。

| 移动次数 | — | — | 3 | |

#### 预期解

1. 将斜面镜切到 `\` 朝向，放置于 (5,2)。
2. 光路：(0,2) → (1,2)…(4,2) → (5,2) 镜面 `\`：`→` 反射为 `↓` → (5,3) → (5,4) 滤光片：`↓` 与水平薄膜面不平行，穿过，白光变红光 → (5,5) → (5,6) 红色水晶点亮。

#### 教学提示文案

> 彩色水晶只认同色的光。让白光穿过彩色薄膜，它就被"染"成那种颜色。注意：光要穿过薄膜面，顺着薄膜方向飞会撞上棱角。

#### 验证要点

- 口袋结构保证：任何到达红色水晶的光必须经过 (5,5) 向下，即必然穿过 (5,4) 滤光片，不存在绕过滤光片的白光路径。
- 若玩家把镜子放在第 2 行其他列：`/` 向上射出边界、`\` 向下撞墙或射出口袋外，均无反馈点亮——促使玩家对齐第 5 列。
- 薄膜朝向教学点：若后续把滤光片换成竖 `|`，`↓` 光线撞棱角停止（本关固定 `—`，此点作为拓展验证）。

> 屏障会把光线完全挡下。规划一条绕行路线，让一束光依次点亮所有水晶——水晶点亮后不会熄灭，光可以继续前进。

#### 验证要点

- 直接沿第 4 行向右的光线会在 (7,4) 屏障处停止——玩家必经绕行，体验"屏障阻挡光线"规则。
- 绕行列不唯一：首镜放 (6,4)、次镜放 (6,6) 也可行；验收接受任意点亮全部 3 水晶的解。
- 若跳过 (2,4) 滤光片则红色水晶不亮（白光不点亮颜色水晶），保证滤光片必经。
- 光线形态水晶被红光点亮，验证"形态水晶不检查颜色"。

   - → (5,2)/(6,2) 加速器：**快速** → (7,2) 监测器：快速 = 目标，**触发** → (8,2) → (9,2) 光粒形态水晶点亮 → (10,2) → (11,2) 镜 `\`：`→`变`↓`；
   - ↓ (11,3) → (11,4) 屏障（唯一通道）：快速通过，降为**标准** → (11,5)/(11,6) 减速器：降为**慢速** → (11,7) → (11,8) 镜 `/`：`↓`变`←`；
   - ← (10,8)(9,8) → (8,8) 转换器 2：慢速光粒变为**白色 RAY**（速度丢弃）→ (7,8) 光线形态水晶点亮 → (6,8) 红滤光片（`←` 穿过竖直薄膜）变**红光** → (5,8) → (4,8) 红色水晶点亮 → (3,8) → (2,8) 基础水晶点亮 → 向左射出边界。

#### 教学提示文案

> 最终考验：光线与光粒的特性你都要用上。颜色属于光线，速度属于光粒——转换的瞬间，它们各归各位。

#### 验证要点

- 第 4 行墙段使 (11,4) 屏障成为唯一下行通道；玩家不可绕开屏障。
- 加速器必须在转换器 1 与监测器之间（(5,2)/(6,2)），否则监测器不触发。
- 减速器放屏障之前会使光粒慢速撞屏障停止；本关减速器同样是"富余但建议"机关（见 §8）。
- 若玩家以 PARTICLE 开局：光粒在 (2,2) 绿滤光片处被阻挡——一次免费的规则复习。
- 红色滤光片位于回程，白光必须先转换再滤色，保证"颜色不可跨越转换"规则被完整体验。

## 7. 落地与验收

### 7.1 文件与命名

按现有仓库结构落地：

```
levels/campaign/ray_chapter/level_ray_002.tscn … level_ray_005.tscn      （R1–R4）
levels/campaign/particle_chapter/level_particle_001.tscn … 003.tscn      （P1–P3）
levels/campaign/mixed_chapter/level_mixed_001.tscn … 003.tscn            （M1–M3）
```

（《2教学+2综合》文档中的 `ray_level_XX` 命名与仓库实际的 `level_ray_XXX` 不一致，本方案以仓库现状为准。）

### 7.2 制作流程

按《美术资源替换与 Godot 关卡编辑指南》：复制 `level_template.tscn` → 绘制地形/墙/合法区 → 摆放预置机关与水晶 → 配置机关栏库存与移动次数 → 运行自检（Diagnostics）→ 手动按预期解通关一遍。

### 7.3 每关必过检查

1. 预期解逐格走通，光路与本文 §3–§5 的格子序列一致；
2. 所有陷阱分支的反馈符合描述（停止/不点亮，而非报错）；
3. 光屏障两侧有护墙；滤光片薄膜朝向与配置表一致；
4. 监测器关卡确认触发事件已接入通关条件（D-1 落地后）；
5. R 重置后库存、朝向、水晶状态全部还原。

## 8. 风险与待确认项

| # | 事项 | 说明 |
|---|---|---|
| D-1 | 监测器触发作为通关条件 | 监测器规则只定义"触发一次事件"，事件语义未定稿。P1/P3/M3 依赖"全部监测器触发 + 全部水晶点亮"作为通关条件，需与程序确认事件接法；若事件系统未就绪，可临时降级为"水晶全亮即通关"，教学价值不受影响 |
| D-2 | 转换器保持入射方向 | 转换器规则文档未显式写明出射方向，本方案按"保持入射方向"设计（M1/M2/M3 的垂直链路依赖此行为），实装时需验证 |
| D-3 | 双格平面镜仅出现于 R2 | 双格镜只与斜向光交互，而斜向光无法与正交机关（屏障/监测器/单格镜）在同一条光路中混用，故未强行塞入其他关卡。若需要更多曝光，建议后续追加"斜向长廊"扩展关（发射器斜射 + 双格镜二连反射） |
| D-4 | P3/M3 的减速器必要性 | 两关的减速器不影响通关判定（慢速也能点亮水晶），作用是建立速度管理习惯与对称手感。若团队要求"库存零富余"，可移除减速器或把终点水晶换成对速度敏感的监测器门禁 |
| D-5 | 未实装机关依赖 | 光屏障、加速器、减速器、监测器、转换器、滤光片、全部水晶变体当前均为 ⏳ 状态。本方案可先以灰盒机关占位制作，实装完成后回归验证 |
| D-6 | 光粒反射规则未验证 | 单格斜面镜/双格平面镜对光粒的反射为预定义规则（⏳），P3 的镜面转向依赖它，需在光粒系统实装后优先回归 |
