# 《光速奇点》永久视觉与关卡编辑接口设计 v1.0

> 适用人员：陈俊贤（主程 / 技术负责人）
> 协作对象：潘陈俣（玩法系统）、张梓涵（关卡、美术与内容）
> 引擎：Godot 4.6.1 Standard
> 语言：静态类型 GDScript
> 当前世界逻辑格：64×64 世界像素
> 文档目标：建立一套后续长期使用的稳定接口，使张梓涵能够通过 Inspector、场景实例和资源文件完成素材替换、道具图标配置、拖拽视觉配置、固定物件移动、新建和复制，而不需要修改核心玩法脚本。

---

# 1. 最终目标

完成本接口体系后，团队的开发关系应当变成：

```text
潘陈俣修改玩法状态
        ↓
陈俊贤维护稳定的公共接口
        ↓
视觉组件根据状态选择纹理
        ↓
张梓涵只配置图片、场景实例、Cell和关卡内容
```

张梓涵以后应当能够完成：

```text
导入PNG
→ 在视觉资源中填写图片
→ 在关卡中实例化物件
→ 修改Cell或在2D视图拖动后吸附
→ Ctrl+D复制墙体、水晶等对象
→ 保存并运行
```

他不应再需要修改：

```text
光传播脚本
OccupancyRegistry
运行状态
镜面反射公式
水晶点亮逻辑
拖拽事务
库存计算
R重置逻辑
```

# 2. “永久接口”的含义

永久接口不是指代码以后绝对不能修改，而是指：

1. **调用方式稳定**：玩法代码通过固定方法改变状态，不直接操作纹理节点。
2. **资源配置稳定**：美术通过 `.tres` 和 Inspector 配图，不在脚本中写死图片路径。
3. **位置接口稳定**：关卡物件使用 `Vector2i cell`，不让逻辑坐标和像素位置分离。
4. **场景结构稳定**：核心节点名和组件职责固定。
5. **实现可替换**：未来从常量网格迁移到 TileMapLayer 时，调用方尽量不变。
6. **错误可发现**：缺纹理、重复格子、多个主发射器等配置错误在启动时明确报告。
7. **不建立全局巨型管理器**：接口按职责拆分，不创建包办所有内容的 `GameManager` 或 `VisualManager`。

永久接口需要冻结的是“契约”，不是每一行内部实现。

# 5. 接口一：GridMetrics

## 5.1 职责

`GridMetrics` 是世界网格尺寸的唯一基础来源。

当前已经存在：

```text
gameplay/grid/grid_metrics.gd
```

应继续保持：

```gdscript
const CELL_SIZE: int = 64
const HALF_CELL_SIZE: float = 32.0
const SINGLE_CELL_WORLD_SIZE: Vector2 = Vector2(64.0, 64.0)
```

## 5.2 永久约束

`GridMetrics` 只负责静态度量，不负责：

```text
地图数据
放置合法性
OccupancyRegistry
场景树查询
关卡对象列表
玩家输入
```

未来正式使用 TileMapLayer 后，坐标换算内部可以迁移，但其他系统仍应继续使用 `Vector2i`。

# 6. 接口二：GridPlacedObject

## 6.1 解决的问题

当前原型中可能同时存在：

```text
脚本内的 emitter_cell / wall_cells / crystal.cell
+
场景中的像素位置
```

如果张梓涵只移动画面节点，逻辑坐标不会自动更新。

`GridPlacedObject` 的目标是：

```text
一个对象只有一份逻辑格事实：cell
```

场景位置由 `cell` 自动刷新。

## 6.2 公共契约

建议创建：

```text
gameplay/grid/grid_placed_object.gd
```

公共接口：

```gdscript
class_name GridPlacedObject
extends Node2D

var cell: Vector2i

func set_cell(next_cell: Vector2i) -> void
func get_cell() -> Vector2i
func get_occupied_offsets() -> Array[Vector2i]
func get_occupied_cells() -> Array[Vector2i]
func sync_world_position() -> void
func snap_from_editor_position() -> void
func validate_grid_object() -> PackedStringArray
```

## 6.3 设计要求

### `cell`

- 是逻辑格唯一事实来源；
- Inspector中修改后自动移动节点；
- 不允许子类再建立第二个位置变量。

### `get_occupied_offsets()`

单格对象默认返回：

```gdscript
[Vector2i.ZERO]
```

未来两格、三格、四格机关通过覆盖该函数返回相对占用格。

### `get_occupied_cells()`

统一计算：

```text
cell + occupied_offset
```

以后占用、关卡校验、静态阻挡和多格物件都使用同一个接口。

## 6.4 编辑器操作

建议使用 `@tool`，提供两种操作方式：

### 方法A：直接修改Cell

```text
选中水晶
→ Inspector中Cell改为(6,4)
→ 节点自动吸附到该格中心
```

### 方法B：拖动后回写Cell

```text
在2D视图拖动物件
→ 点击“吸附当前位置并回写格坐标”
→ 自动计算Cell并吸附
```

## 6.5 重要边界

`GridPlacedObject` 不负责：

```text
目标格是否合法
是否与墙体重叠
是否可以在运行阶段移动
OccupancyRegistry写入
库存数量
```

它只负责“对象在哪个格、占哪些格、世界位置如何同步”。

# 7. 接口三：VisualStateTexture

## 7.1 解决的问题

不同对象有不同内容状态：

```text
镜面：slash / backslash
水晶：unlit / lit
电控门：closed / open
滤光片：red / green / blue
转换器：不同输入输出模式
```

不能为每个状态都在核心控制器里写死图片路径。

## 7.2 资源结构

创建：

```text
gameplay/visuals/visual_state_texture.gd
```

```gdscript
class_name VisualStateTexture
extends Resource

## 状态的稳定ID，例如slash、backslash、unlit、lit。
@export var state_id: StringName = &"default"

## 对象正式放置在世界中时显示的纹理。
@export var world_texture: Texture2D

## 对象作为拖拽预览时显示的纹理。
## 可为空；为空时回退到world_texture。
@export var drag_texture: Texture2D
```

## 7.3 状态ID规则

状态ID使用稳定的小写英文：

```text
default
slash
backslash
unlit
lit
open
closed
red
green
blue
```

不要使用：

```text
状态1
新状态
最终版
镜子左边图片
```

状态ID属于代码契约，图片文件名可以调整，但状态ID尽量不变。

# 8. 接口四：ObjectVisualProfile

## 8.1 解决的问题

同一个物件可能需要：

- 道具栏图标；
- 世界正式图片；
- 拖拽图片；
- 多个内部状态图片；
- 缺失拖拽图时回退到正式图片。

因此建立一个统一视觉资源。

## 8.2 公共结构

创建：

```text
gameplay/visuals/object_visual_profile.gd
```

```gdscript
class_name ObjectVisualProfile
extends Resource

## 道具栏使用的独立UI图标。
## 固定物件可以留空。
@export var inventory_icon: Texture2D

## 默认内容状态ID。
@export var default_state_id: StringName = &"default"

## 该对象全部内容状态的纹理定义。
@export var states: Array[VisualStateTexture] = []
```

公共方法：

```gdscript
func get_world_texture(state_id: StringName) -> Texture2D
func get_drag_texture(state_id: StringName) -> Texture2D
func has_state(state_id: StringName) -> bool
func validate_profile() -> PackedStringArray
```

## 8.3 回退规则

`get_drag_texture()` 应遵循：

```text
存在专用拖拽图片
→ 返回drag_texture

没有专用拖拽图片
→ 返回同状态world_texture
```

这样张梓涵不必为每个道具都额外制作拖拽图。

## 8.4 张梓涵如何使用

镜面资源：

```text
mirror_single_visuals.tres

Inventory Icon
→ mirror_inventory_icon.png

States
├─ state_id = slash
│  ├─ world_texture = mirror_slash_world.png
│  └─ drag_texture = 可留空
└─ state_id = backslash
   ├─ world_texture = mirror_backslash_world.png
   └─ drag_texture = 可留空
```

水晶资源：

```text
crystal_basic_visuals.tres

Inventory Icon
→ 空

States
├─ state_id = unlit
│  └─ world_texture = crystal_unlit.png
└─ state_id = lit
   └─ world_texture = crystal_lit.png
```

# 9. 接口五：ObjectVisualView

## 9.1 职责

`ObjectVisualView` 是统一的运行时显示组件。

它只处理：

```text
当前内容状态
正式/拖拽显示模式
合法/非法/禁用反馈
纹理刷新
缺失资源回退
```

它不处理：

```text
镜面反射
水晶激活条件
库存扣减
放置合法性
运行状态
```

## 9.2 推荐场景结构

```text
ObjectVisualView: Node2D
├─ Shadow: ColorRect
├─ Artwork: TextureRect
├─ FeedbackOverlay: ColorRect
└─ DebugMark: CanvasItem
```

### `Artwork`

- 承载正式美术；
- 世界对象矩形为 `-32～32`；
- 正常状态保持 `Color.WHITE`；
- 不再由玩法脚本直接访问。

### `FeedbackOverlay`

- 绿色合法反馈；
- 红色非法反馈；
- 不改变原始图片；
- 默认隐藏；
- `mouse_filter = Ignore`。

### `DebugMark`

- 镜面方向线等临时调试标记；
- 正式图片齐全后可以隐藏；
- 不参与玩法逻辑。

## 9.3 公共契约

```gdscript
enum DisplayMode {
	WORLD,
	DRAG_PREVIEW,
}

enum FeedbackState {
	NONE,
	VALID,
	INVALID,
	DISABLED,
}
```

公开方法：

```gdscript
func set_profile(next_profile: ObjectVisualProfile) -> void
func set_content_state(state_id: StringName) -> void
func set_display_mode(mode: DisplayMode) -> void
func set_feedback(feedback: FeedbackState) -> void
func set_visual_visible(is_visible: bool) -> void
func refresh_visual() -> void
```

## 9.4 核心原则

玩法对象只调用：

```gdscript
_visual_view.set_content_state(&"slash")
_visual_view.set_display_mode(ObjectVisualView.DisplayMode.DRAG_PREVIEW)
_visual_view.set_feedback(ObjectVisualView.FeedbackState.INVALID)
```

不要再调用：

```gdscript
_body.color = ...
_visual.texture = ...
_visual.self_modulate = ...
```

具体节点和属性只允许 `ObjectVisualView` 自己操作。

这就是永久视觉接口最重要的边界。

# 10. 接口六：PlaceableItemDefinition

## 10.1 解决的问题

当前原型只有一种镜面，控制器中可能写死：

```text
prototype_token_scene
prototype_token_remaining
prototype_slot_icon
```

未来加入加速器、减速器、滤光片、分光器后，这种写法会迅速膨胀。

## 10.2 资源结构

创建：

```text
gameplay/items/placeable_item_definition.gd
```

```gdscript
class_name PlaceableItemDefinition
extends Resource

## 道具类型唯一ID。
@export var item_id: StringName

## UI显示名称。
@export var display_name: String

## 从机关栏拿取时实例化的场景。
@export var packed_scene: PackedScene

## 世界、拖拽和道具栏共用的视觉资源。
@export var visual_profile: ObjectVisualProfile

## 新实例默认内容状态。
@export var default_state_id: StringName = &"default"
```

公共方法：

```gdscript
func validate_definition() -> PackedStringArray
```

## 10.3 镜面定义示例

```text
mirror_single_item.tres

Item ID
→ mirror_single

Display Name
→ 单格斜面镜

Packed Scene
→ single_cell_mirror.tscn

Visual Profile
→ mirror_single_visuals.tres

Default State ID
→ slash
```

以后机关栏不再需要知道“镜面有哪些图片”，只读取定义资源。

```text
gameplay/items/inventory_slot_view.gd
```

# 13. 接口九：PlaceableToken

## 13.1 永久职责

`PlaceableToken` 是所有玩家可放置机关的基础类，负责：

- `mechanism_id`
- `cell`
- 世界位置
- 正式与拖拽显示模式
- 通用合法/非法反馈
- 视觉组件引用
- 道具定义引用

- 具体机关内部状态；
- 光学功能；
- 反射；
- 库存；
- 占用登记；
- RunState权限。

```gdscript
func configure(

func get_content_state_id() -> StringName
```

## 13.3 子类覆盖点

# 14. 接口十：SingleCellMirror

## 14.1 状态事实

镜面唯一内部事实仍然是：

```gdscript
orientation
```

视觉状态ID由它映射：

```text
SLASH     → slash
BACKSLASH → backslash
```

## 14.2 公共接口

```gdscript
func set_orientation(next_orientation: MirrorOrientation) -> void
func toggle_orientation() -> void
func reflect_direction(incoming_direction: Vector2i) -> Vector2i
func get_content_state_id() -> StringName
func reset_configuration() -> void
```

## 14.3 视觉同步规则

所有朝向变化必须调用：

```gdscript
set_orientation(...)
```

禁止在其他地方直接写：

```gdscript
orientation = ...
```

`set_orientation()`内部：

```text
更新orientation
→ 刷新视觉state_id
```

反射逻辑和视觉都读取同一个 `orientation`，保证不会出现图片与反射规则不一致。

## 14.4 拖拽状态

拖动 `/` 镜面时：

```text
content_state = slash
display_mode = DRAG_PREVIEW
```

拖动 `\` 镜面时：

```text
content_state = backslash
display_mode = DRAG_PREVIEW
```

非法目标只改变：

```text
feedback = INVALID
```

不能改变镜面方向。

# 15. 接口十一：BasicCrystal

## 15.1 永久状态

```gdscript
is_activated: bool
```

视觉状态映射：

```text
false → unlit
true  → lit
```

## 15.2 公共接口

```gdscript
func activate() -> void
func reset_runtime() -> void
func refresh_visual() -> void
```

## 15.3 视觉策略

删除旧透明度方案：

```text
_UNLIT_ALPHA
_LIT_ALPHA
_base_color
ColorRect.color
```

改为两张图片切换：

```gdscript
func refresh_visual() -> void:
	_visual_view.set_content_state(
		&"lit" if is_activated else &"unlit"
	)
```

## 15.4 生命周期不变

```text
初始unlit
→ 光合法命中
→ activate()
→ lit
→ 光路视觉消失
→ 仍保持lit
→ R
→ reset_runtime()
→ unlit
```

视觉改变不能修改水晶玩法生命周期。

# 17. 接口十三：WallCell

## 17.1 临时最小关卡用途

第二阶段最小关卡可以使用：

```text
WallCell: GridPlacedObject
└─ ObjectVisualView
```

张梓涵通过：

```text
实例化
→ Ctrl+D
→ 修改Cell
```

快速复制多格墙。

## 17.2 永久边界

`WallCell`适合：

- 原型；
- 少量特殊墙；
- 需要独立节点状态的可消除墙。

大量普通固定墙最终应进入 TileMapLayer。

## 17.3 公共接口

```gdscript
func blocks_light() -> bool
func is_removable_wall() -> bool
func is_currently_active() -> bool
```

普通固定墙默认：

```text
blocks_light = true
removable = false
active = true
```

# 18. 接口十四：LevelObjectRegistry

## 18.1 解决的问题

当前控制器中存在硬编码：

```gdscript
emitter_cell
wall_cells
crystals = [$RuntimeObjects/Crystal]
```

这导致张梓涵不能简单复制或移动对象。

`LevelObjectRegistry`负责：

```text
从关卡场景收集固定对象
校验配置
向控制器提供查询
```

## 18.2 推荐场景结构

```text
LevelObjects
├─ Emitters
├─ Crystals
├─ Walls
└─ PresetMechanisms
```

张梓涵把对象实例放入相应容器。

## 18.3 公共契约

```gdscript
func rebuild_from_scene() -> bool

func get_primary_emitter() -> FixedEmitter
func get_crystals() -> Array[BasicCrystal]
func get_wall_cells() -> Array[Vector2i]
func get_static_blocked_cells() -> Array[Vector2i]
func get_preset_mechanisms() -> Array[GridPlacedObject]

func validate_level_objects() -> PackedStringArray
```

## 18.4 校验内容

至少检查：

- 主发射器恰好一个；
- 所有对象在地图边界内；
- 墙体无重复格；
- 水晶无重复格；
- 发射器、水晶、墙体不重叠；
- 多格对象全部占用格合法；
- 视觉资源不缺失；
- 水晶至少一颗；
- 对象类型与容器匹配。

## 18.5 控制器使用方式

发射时：

```gdscript
var emitter: FixedEmitter = level_registry.get_primary_emitter()
var current_cell: Vector2i = emitter.get_emission_cell()
var direction: Vector2i = emitter.get_emission_direction()
```

墙体查询：

```gdscript
return level_registry.get_wall_cells().has(cell)
```

水晶遍历：

```gdscript
for crystal: BasicCrystal in level_registry.get_crystals():
	...
```

控制器不再维护第二份硬编码关卡内容。

# 19. 张梓涵的最终工作流程

## 19.1 替换镜面资源

```text
打开 mirror_single_visuals.tres
→ Inventory Icon填道具栏图片
→ slash填“/”世界图
→ backslash填“\”世界图
→ 可选填写拖拽图
→ 保存
```

## 19.2 替换水晶资源

```text
打开 crystal_basic_visuals.tres
→ unlit填未点亮图片
→ lit填点亮图片
→ 保存
```

## 19.3 新建水晶

```text
将 basic_crystal.tscn 拖到 LevelObjects/Crystals
→ 设置Cell
→ 需要不同外观时覆盖visual_profile
→ 保存
```

## 19.4 移动水晶或发射器

推荐方式：

```text
选中根节点
→ 修改Cell
```

或者：

```text
在2D视图拖动
→ 点击“吸附当前位置并回写格坐标”
```

## 19.5 复制墙体

```text
选中WallCell
→ Ctrl+D
→ 修改Cell
→ 重复
```

正式大量墙体以后使用 TileMapLayer 绘制。

## 19.6 新建道具栏道具

```text
创建新的PlaceableItemDefinition
→ 选择PackedScene
→ 选择ObjectVisualProfile
→ 在关卡库存中增加LevelInventoryEntry
→ 设置数量
```

不需要修改核心控制器中的图标路径或场景路径。

# 20. 迁移当前代码的实施顺序

为了降低风险，建议分六批实施。

## 第一批：资源数据和显示组件

先使用临时纹理验证：


不修改玩法逻辑。

## 第二批：水晶和镜面接入

```text
BasicCrystal
PlaceableToken

```

目标：

```text
水晶：unlit / lit图片切换
镜面：slash / backslash图片切换
拖拽：保留方向并叠加合法性反馈
```

## 第三批：道具定义和道具栏

创建：

```text
PlaceableItemDefinition
LevelInventoryEntry
InventorySlotView
```

把当前：

```text
prototype_token_scene
prototype_slot_icon
prototype_token_remaining
```

逐步迁移到定义资源和栏位组件。

## 第四批：GridPlacedObject和可复用固定场景

创建：

```text
GridPlacedObject
FixedEmitter
BasicCrystal独立场景
WallCell
```

使张梓涵可以实例化、复制和修改Cell。

## 第六批：完整回归和文档冻结

- 将接口契约写入开发规范；
- 标记禁止直接访问视觉子节点；
- 标记禁止在控制器中硬编码图片路径；

# 21. 永久开发规则

以后所有新机关必须遵守。

## 21.1 图片路径

禁止：

```gdscript
var texture = preload("res://assets/art/xxx.png")
```

散落在控制器和玩法脚本中。

图片统一进入：

```text
ObjectVisualProfile
```

## 21.2 视觉节点访问

禁止玩法脚本直接写：

```gdscript
$TokenBody.texture = ...
$TokenBody.color = ...
$TokenBody.self_modulate = ...
```

必须调用：

```gdscript
ObjectVisualView
```

## 21.3 内部状态

每种机关保留自己的唯一状态事实：

```text
镜面：orientation
水晶：is_activated
门：is_open
滤光片：filter_color
转换器：conversion_mode
```

状态变化后统一刷新视觉。

## 21.4 格子位置

禁止同时维护：

```text
cell
+
手写世界position
```

逻辑对象必须通过 `GridPlacedObject` 同步。

## 21.5 道具栏

道具栏必须读取：

```text
PlaceableItemDefinition
```

不为每种机关在核心控制器里新增一组硬编码字段。

## 21.6 关卡固定对象

固定发射器、水晶、少量特殊墙和预置机关必须以场景实例存在，由 `LevelObjectRegistry` 收集。

## 21.7 大量普通墙

大量静态地形最终使用 TileMapLayer，不堆积大量独立场景节点。

# 24. 陈俊贤、潘陈俣、张梓涵各自使用方式

## 陈俊贤

负责：

- 实现和维护公共接口；
- 审查节点结构和资源契约；
- 保证玩法代码不直接接触纹理节点；
- 保证关卡对象只有一份格子事实；

负责：

- 只修改玩法状态；

```gdscript
mirror.set_orientation(...)
crystal.activate()
```

不写：

```gdscript
mirror_art.texture = ...
crystal_visual.self_modulate = ...
```

- 实例化固定关卡对象；
- 修改Cell；
- 复制墙体和水晶；
- 记录素材来源；
- 检查画面和教学可读性。

不修改核心 `.gd`。

# 25. 最终验收标准

这套接口完成的标志不是“所有ColorRect都变成TextureRect”，而是：

```text
张梓涵可以在不修改GDScript的情况下：

1. 替换道具栏图标；
2. 替换道具正式世界图片；
3. 替换道具拖拽图片；
4. 配置镜面两种方向图片；
5. 配置水晶点亮和未点亮图片；
6. 新建和复制墙体；
7. 新建和移动水晶；
8. 移动固定发射器；
9. 增加新的道具库存条目；
10. 运行后得到正确玩法结果。
```

同时：

```text
潘陈俣可以增加机关状态，
而不需要知道图片节点结构；

陈俊贤可以替换视觉实现，
而不需要重写玩法状态和关卡内容。
```

这才是一套适合后续持续开发的永久接口。
