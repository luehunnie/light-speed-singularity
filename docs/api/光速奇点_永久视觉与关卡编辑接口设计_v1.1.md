# 1. 文档定位

本文件定义长期稳定的接口契约，不等于所有接口已经完成。

全文使用三种状态标记：

- **【当前已实现】**：当前工程已经存在并接入运行原型；
- **【当前部分实现】**：已有可复用基础，但仍有职责留在核心原型中；
- **【目标接口】**：已经冻结方向，但尚未完整实现。

发生冲突时，优先级如下：

1. 最新正式玩法、开发规范、技术栈和目录结构文档；
2. 本接口契约；
3. 美术与关卡编辑操作指南；
4. 当前真实代码、场景和资源；
5. 本地 AI 协作文档；
6. 历史归档。

当前真实代码仍是核心闭环原型。空目录、占位 `.gitkeep` 和本文件中的目标接口不得被写成已经完成。

# 2. 永久接口的固定原则

永久接口冻结的是调用方式、职责边界和数据语义，不冻结内部每一行实现。

必须长期保持：

1. **逻辑位置唯一**：世界对象使用 `Vector2i cell` 或锚点格作为唯一位置事实；
2. **视觉不反向修改玩法**：视觉组件只显示逻辑状态；
3. **资源不写死在核心代码中**：可替换图片通过 `.tres` Profile 配置；
4. **世界纹理和 UI 图标分离**；
5. **大量地图内容使用 TileMapLayer，独立逻辑对象使用场景实例**；
6. **关卡对象支持 Inspector 配置、拖动、复制和 64 格吸附**；
7. **关卡错误通过只读校验报告，不静默自动修复**；
8. **核心协调层不直接操作具体纹理节点**；
9. **现有原型采用行为保持式迁移，不推倒重写**；
10. **不创建包办网格、关卡、视觉、库存和传播的巨型管理器**。

# 6. 固定对象接口：GridPlacedObject

## 6.1 状态

**【目标接口】**

目标路径：

```text
gameplay/grid/grid_placed_object.gd
```

## 6.2 核心数据

```gdscript
@export var cell: Vector2i = Vector2i.ZERO
```

多格对象使用：

```gdscript
@export var occupied_offsets: Array[Vector2i] = [Vector2i.ZERO]
```

语义：

- `cell` 是锚点格；
- `occupied_offsets` 是相对锚点的占用偏移；
- 世界 `position` 是显示结果，不是第二份逻辑事实；
- 子类不得重新建立 `emitter_cell`、`crystal_cell` 等平行位置字段。

## 6.3 稳定公共接口

```gdscript
func set_cell(next_cell: Vector2i) -> void
func get_cell() -> Vector2i
func get_anchor_cell() -> Vector2i
func get_occupied_offsets() -> Array[Vector2i]
func get_occupied_cells() -> Array[Vector2i]
func sync_world_position_from_cell() -> void
func snap_editor_position_to_grid() -> void
func validate_grid_object() -> PackedStringArray
```

## 6.4 编辑器要求

建议使用 `@tool`：

```text
Inspector 修改 cell
→ 自动同步世界位置

2D 视图拖动根节点
→ 换算最近格
→ 更新 cell
→ 吸附到格中心
```

只允许移动对象根节点。禁止只移动 `Artwork`、阴影、反馈层或碰撞子节点。

## 6.5 明确不负责

- 目标格是否合法；
- 是否允许玩家移动；
- 占用登记；
- 库存扣减；
- 光传播；
- 通关判断；
- 自动修复关卡冲突。

# 16. TileMapLayer 关卡接口

## 16.1 目标关卡层

**【目标接口】**

```text
TerrainLayer
WallLayer
LegalAreaLayer
DecorationLayer
```

## 16.2 TerrainLayer

负责：

- 地面；
- 地图形状；
- 基础可见区域。

地面存在不代表一定允许玩家放置。

## 16.3 WallLayer

大量普通墙体使用 TileMapLayer 绘制。

Tile 自定义数据建议统一提供：

```text
blocks_ray
blocks_particle
is_destructible
```

具体字段名冻结后必须同步到 TileSet、`LevelWorldQuery`、校验器和操作指南。

少量特殊墙、可消除墙或带独立状态的墙使用独立场景对象，不用大量节点替代普通墙层。

## 16.4 LegalAreaLayer

负责标记允许玩家放置机关的格子。

放置合法性采用：

```text
允许区域
+
统一阻挡/占用黑名单查询
```

不得维护少量“白名单机关格”硬编码数组。

## 16.5 DecorationLayer

只负责装饰。

装饰不得承担隐藏阻挡、可放置、目标或光学规则。

# 17. 关卡对象注册器：LevelObjectRegistry

## 17.1 状态

**【目标接口】**

目标路径：

```text
gameplay/level/level_object_registry.gd
```

## 17.2 职责

扫描并注册：

- 主发射器；
- 水晶；
- 预置机关；
- 特殊墙；
- 受控对象；
- 关卡目标对象。

提供按以下维度查询：

- Cell；
- 对象 ID；
- 对象类型；
- 目标组；
- 容器。

## 17.3 稳定公共接口

```gdscript
func rebuild_from_scene() -> bool
func get_primary_emitter() -> FixedEmitter
func get_crystals() -> Array[BasicCrystal]
func get_preset_mechanisms() -> Array[GridPlacedObject]
func get_special_walls() -> Array[GridPlacedObject]
func get_objects_at(cell: Vector2i) -> Array[GridPlacedObject]
func validate_registered_objects() -> PackedStringArray
func build_debug_snapshot() -> Dictionary
```

注册器不读取或修改玩家运行时库存，不替代 `OccupancyRegistry`。

# 18. 关卡校验器：LevelValidator

## 18.1 状态

**【目标接口】**

目标路径：

```text
gameplay/level/level_validator.gd
```

## 18.2 校验内容

至少检查：

- 主发射器恰好一个；
- 所有固定对象在地图边界内；
- 固定对象占用不重复；
- 发射器、水晶、特殊墙和预置机关不非法重叠；
- 多格对象全部占用格合法；
- 发射方向合法；
- 光形态合法；
- 视觉 Profile 缺失；
- 必需状态 ID 缺失；
- 关卡至少有一个必需目标；
- 库存条目 ID 重复；
- 关卡库存定义缺失；
- 同时组和顺序组配置冲突；
- Tile 自定义数据缺失。

校验器只报告问题，不自动移动、删除、补齐或修复对象。

# 20. 多格对象接口

多格对象统一使用：

```text
anchor cell
+
occupied_offsets
```

示例：

```text
anchor_cell = (4, 3)
occupied_offsets = [(0, 0), (1, 0)]
```

规则：

- 关卡人员只移动根节点和锚点；
- 全部占用格由接口计算；
- 不在 Inspector 手工维护每个绝对占用格；
- 旋转多格对象时必须同步更新占用偏移；
- 注册、放置、查询和校验使用同一组占用格。

# 24. 接口依赖方向

允许：

```text
关卡场景
→ 配置 Resource 和固定对象场景

核心协调层
→ 注册器、控制器和公共协议

光执行模块
→ LightWorldQuery

玩法对象
→ ObjectVisualView

UI
→ 发出玩家意图、接收状态信号

Diagnostics
→ 调用公开 validate / snapshot 接口
```

禁止：

- 视觉组件修改传播、库存、目标或运行状态；
- UI 直接写库存内部字段；
- 关卡脚本直接修改光执行内部状态；
- `GridPlacedObject` 访问库存；
- `LevelObjectRegistry` 替代玩家动态占用表；
- `OccupancyRegistry` 读取像素位置；
- `LevelValidator` 自动修复关卡；
- 发射器直接运行光线或光粒算法；
- 光执行模块直接操作 UI；
- 核心循环直接访问具体纹理节点。

# 28. 最终验收标准

接口完成后，美术与关卡制作人员必须能够在不修改核心 GDScript 的情况下：

1. 替换道具栏图标；
2. 替换对象世界纹理；
3. 替换拖拽纹理；
4. 配置镜面两种方向；
5. 配置水晶点亮和未点亮视觉；
6. 配置光线路段四方向纹理；
7. 配置发射器光线/光粒视觉和四方向；
8. 使用 TileMapLayer 绘制地面、普通墙、合法区域和装饰；
9. 新建、移动和复制固定发射器、水晶和预置机关；
10. 使用锚点和偏移配置多格机关；
11. 配置关卡库存和运行参数；
12. 运行关卡校验；
13. 制作单机关、组合、灰盒和正式章节关卡；
14. 得到与逻辑配置一致的玩法结果。

同时：

- 玩法人员只修改状态和规则，不直接操作纹理节点；
- 技术人员可以替换视觉内部实现，而不重写玩法状态；
- 核心循环不因新增图片、机关或关卡而继续膨胀；
- 所有运行日志、快照和存档写入 `user://`，不写入仓库资源目录。
