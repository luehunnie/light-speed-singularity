# 2. 永久接口的固定原则

永久接口冻结的是调用方式、职责边界和数据语义，不冻结内部每一行实现。

必须长期保持：

1. **逻辑位置唯一**：固定对象以场景编辑 `position` 为位置事实，`cell` 由 `position` 经 `world_to_cell` 确定性派生；玩家放置对象以锚点格作为唯一位置事实；
2. **视觉不反向修改玩法**：视觉组件只显示逻辑状态；
3. **资源不写死在核心代码中**：可替换图片通过 `.tres` Profile 配置；
4. **世界纹理和 UI 图标分离**；
5. **大量地图内容使用 TileMapLayer，独立逻辑对象使用场景实例**；
6. **关卡对象支持 Inspector 配置、拖动、复制和 64 格吸附**：由 Godot 原生负责节点拖动、复制、64×64 网格吸附和 `position` 的 Undo/Redo，不另建编辑器侧吸附机制；
7. **关卡错误通过只读校验报告，不静默自动修复**；
8. **核心协调层不直接操作具体纹理节点**；
9. **现有原型采用行为保持式迁移，不推倒重写**；
10. **不创建包办网格、关卡、视觉、库存和传播的巨型管理器**；
11. **运行时与 addons 解耦**：运行时代码不得依赖 `addons/`，两个正式插件全部关闭后游戏正常运行；插件只承担美术资源编辑与关卡辅助，不承载玩法事实。

# 6. 固定对象接口：GridPlacedObject

## 6.1 状态

**【目标接口，待重构】** —— 当前 D1 为旧 `cell→position` 实现，D3A 重构尚未完成。

`gameplay/grid/grid_placed_object.gd` 当前为 D1 旧实现：以 `cell` 为事实、由 `cell` 同步 `position`。D3A 重构目标为反转该关系：以场景编辑 `position` 为事实，`cell` 由 `position` 派生。重构落地前，本节位置契约**当前不能作为关卡制作、保存或验收的前置条件**。

具体待重构项：

- 位置关系反转：`position` 为场景编辑事实，`cell = world_to_cell(position)`；
- `get_cell()` 改为 `world_to_cell(position)`；
- `set_cell(next_cell)` 改为 `position = cell_to_world(next_cell)`；
- 删除旧 `cell→position` 同步路径与对应 `@tool` setter。

节点拖动、复制、64×64 网格吸附和 `position` 的 Undo/Redo 由 Godot 原生负责，不另建编辑器侧吸附机制。

目标路径：

```text
gameplay/grid/grid_placed_object.gd
```

## 6.2 核心数据

`position`（继承自 `Node2D`）是场景编辑事实。`cell` 不作为独立 `@export` 事实字段，由 `position` 派生：

```gdscript
func get_cell() -> Vector2i:
    return GridMetrics.world_to_cell(position)

func set_cell(next_cell: Vector2i) -> void:
    position = GridMetrics.cell_to_world(next_cell)
```

多格对象使用：

```gdscript
@export var occupied_offsets: Array[Vector2i] = [Vector2i.ZERO]
```

语义：

- `cell` 是锚点格，由 `position` 派生；
- `occupied_offsets` 是相对锚点的占用偏移；
- 场景编辑 `position` 是唯一位置事实，`cell` 不是第二份逻辑事实；
- 子类不得重新建立 `emitter_cell`、`crystal_cell` 等平行位置字段。

## 6.3 稳定公共接口

```gdscript
func set_cell(next_cell: Vector2i) -> void
func get_cell() -> Vector2i
func get_anchor_cell() -> Vector2i
func get_occupied_offsets() -> Array[Vector2i]
func get_occupied_cells() -> Array[Vector2i]
func validate_grid_object() -> PackedStringArray
```

`sync_world_position_from_cell()` / `snap_editor_position_to_grid()` 属于旧 `cell→position` 同步路径，D3A 重构后删除。

## 6.4 编辑器要求

Godot 原生负责：

- 节点拖动；
- 复制；
- 64×64 网格吸附；
- `position` 的 Undo/Redo。

Godot 原生负责节点拖动、复制、64×64 网格吸附和 `position` 的 Undo/Redo，不另建编辑器侧吸附机制。关卡人员通过 Godot 原生 2D 编辑器移动根节点，`cell` 由 `position` 自动派生，无需 Inspector 手工维护 `cell`。

只允许移动对象根节点。禁止只移动 `Artwork`、阴影、反馈层或碰撞子节点。

## 6.5 明确不负责

- 目标格是否合法；
- 是否允许玩家移动；
- 占用登记；
- 库存扣减；
- 光传播；
- 通关判断；
- 自动修复关卡冲突。

## 6.6 关联目标结构（目标 / 未实现）

下列结构为 D3A 及后续阶段目标，当前未实现，最终字段名与方法名以未来实现为准：

- **`EmitterConfigNode`**：发射器关卡配置唯一来源，保存场景位置、默认发射形态、光线八方向默认方向、光粒四方向默认方向、Visual Profile、编辑器预览开关。
- **`EmissionPreview`**：跟随 `EmitterConfigNode` 移动和方向变化的编辑器预览组件，仅用于编辑器预览，不参与玩法判定，不复制完整传播算法。
- **`LightPathLayer`**：独立、固定原点的运行时光路层，只承载运行时真实光路。
- **`RuntimeObjects/Emitter/{EmitterVisual, EmissionPreview}`**：发射器运行时与预览目标节点结构。

`CoreLoopPrototype.emitter_cell` / `emitter_direction` 仍在使用，接入 `EmitterConfigNode` 后退出。

路径：

```text
gameplay/visuals/visual_state_texture.gd
```

`class_name VisualStateTexture`，`extends Resource`。

稳定数据：

```gdscript
@export var state_id: StringName = &"default"
@export var world_texture: Texture2D
@export var drag_texture: Texture2D
```

```gdscript
func validate_state() -> PackedStringArray
```

状态 ID 使用稳定小写英文：

```text
default
slash
backslash
unlit
lit
open
closed
ray
particle
```

不得使用临时编号、中文描述或文件名充当状态 ID。

拖拽纹理为空时，回退到同状态的世界纹理。

路径：

`class_name ObjectVisualProfile`，`extends Resource`。位于 `object_visuals/` 子目录下，不在 `visuals/` 根目录。

稳定数据：

```gdscript
@export var inventory_icon: Texture2D

```

稳定能力：

```gdscript

func get_drag_texture(state_id: StringName) -> Texture2D

```

查找回退规则：传入 `state_id` 非空且存在 → 否则 `default_state_id` → 再失败返回 `null`，不崩溃、不刷屏警告。`get_drag_texture()` 在 `drag_texture` 缺失时回退到**同一最终状态**的 `world_texture`，不跨状态回退。`has_state()` 不使用 `default_state_id` 回退，空 ID 直接返回 `false`。`validate_profile()` 一次返回全部问题，`inventory_icon` 为空与 `drag_texture` 为空均不视为错误。

## 8.2 资源边界

Profile 负责：

- 世界状态纹理；
- 拖拽状态纹理；
- 通用库存图标；
- 状态 ID 校验。

Profile 不负责：

- 光传播颜色；
- 运行状态；
- 机关反射公式；

## 10.1 LightSegmentVisualProfile

**【当前已实现】**

`class_name LightSegmentVisualProfile`，`extends Resource`。位于 `light_segments/` 子目录下，不在 `visuals/` 根目录。与 `ObjectVisualProfile` 平行，不复用 `VisualStateTexture`，因为光线路径段是逐格模型，不存在对象内容状态切换。

```gdscript
@export var horizontal_texture: Texture2D
@export var vertical_texture: Texture2D

```

方向映射：

```text
水平        -
垂直        |
左下到右上  /
左上到右下  \
```

稳定公开方法：

```gdscript
static func is_valid_segment_direction(direction: Vector2i) -> bool
static func get_segment_state_for_direction(direction: Vector2i) -> StringName

```

要点：

- `is_valid_segment_direction()` 判断方向是否属于四正交或四单位斜向（`LEFT/RIGHT/UP/DOWN` 及 `(1,-1)/(-1,1)/(1,1)/(-1,-1)`），`ZERO` 与超单位长度向量返回 `false`；

Profile 只描述线段形状，不保存运行时光颜色。四个纹理全部为空属于合法配置，运行时由 `LightSegmentView` 静默回退到黄色占位块，本资源不输出 warning。

**【当前已实现】**


`class_name LightSegmentView`，`extends Node2D`。位于 `light_segments/` 子目录下，`.gd` 与 `.tscn` 成对存在。

```gdscript
func set_profile(next_profile: LightSegmentVisualProfile) -> void
```

- 旋转多格对象时必须同步更新占用偏移；
- 注册、放置、查询和校验使用同一组占用格。

## 23.5 正式编辑器插件（目标 / 未实现）

运行时代码不得依赖 `addons/`，插件全部关闭后游戏正常运行。

# 24. 接口依赖方向

允许：

```text
关卡场景
→ 配置 Resource 和固定对象场景

核心协调层
→ 注册器、控制器和公共协议

光执行模块
→ LightWorldQuery

玩法对象
→ ObjectVisualView

UI
→ 发出玩家意图、接收状态信号

Diagnostics
→ 调用公开 validate / snapshot 接口
```

禁止：

- 视觉组件修改传播、库存、目标或运行状态；
- UI 直接写库存内部字段；
- 关卡脚本直接修改光执行内部状态；
- `GridPlacedObject` 访问库存；
- `LevelObjectRegistry` 替代玩家动态占用表；
- `OccupancyRegistry` 读取像素位置；
- `LevelValidator` 自动修复关卡；
- 发射器直接运行光线或光粒算法；
- 光执行模块直接操作 UI；
- 核心循环直接访问具体纹理节点。

## 25.1 已经完成并应复用

- `OccupancyRegistry` 轻量双向索引。

## 25.2 尚未完成

- `GridPlacedObject` 位置契约重构（D3A，待重构）：当前 D1 仍是旧 `cell→position` 实现，目标为 `position` 为事实、`cell` 由 `world_to_cell(position)` 派生、`set_cell` 用 `cell_to_world`，尚未实现；节点拖动/复制/64 格吸附/`position` 的 Undo/Redo 由 Godot 原生负责；
- `LevelValidator`；
- 正式 TileMapLayer 墙体与合法区域；
- `PlaceableItemDefinition`；
- `LevelInventoryEntry`；
- `LevelInventoryController`（多道具资源化库存；当前单槽 `InventoryController` 已落地于 `gameplay/placement/`）；
- 完整关卡模板；
- 正式三章节关卡制作链。

部分实现（已落地核心能力，目标契约仍未完整实现）：`FixedEmitter`（运行期 cell/direction 与 `FireRequest` 已实现；`light_form`/统一 `EmissionRequest` 仍为目标）、`LevelObjectRegistry`（水晶双向索引已实现；扫描/多类型对象注册仍为目标）、`LevelWorldQuery`（只读查询已实现；TileMapLayer 合并查询仍为目标）。

## 25.3 迁移原则

- 一次只迁移一个职责；
- 旧行为有回归基线后再抽离；
- 新接口验证通过前不删除旧事实来源；
- 过渡期双重事实必须有明确期限；
- 禁止以“顺手”为理由扩大当前开发批次。

已合并的 Diagnostics foundation 只负责回归基线与诊断基础，不实施本文件中尚未完成的编辑器接口。

# 28. 最终验收标准

接口完成后，美术与关卡制作人员必须能够在不修改核心 GDScript 的情况下：

1. 替换道具栏图标；
2. 替换对象世界纹理；
3. 替换拖拽纹理；
4. 配置镜面两种方向；
5. 配置水晶点亮和未点亮视觉；
6. 配置光线路段四方向纹理；
7. 配置发射器光线/光粒视觉和四方向；
8. 使用 TileMapLayer 绘制地面、普通墙、合法区域和装饰；
9. 新建、移动和复制固定发射器、水晶和预置机关；
10. 使用锚点和偏移配置多格机关；
11. 配置关卡库存和运行参数；
12. 运行关卡校验；
13. 制作单机关、组合、灰盒和正式章节关卡；
14. 得到与逻辑配置一致的玩法结果。

同时：

- 玩法人员只修改状态和规则，不直接操作纹理节点；
- 技术人员可以替换视觉内部实现，而不重写玩法状态；
- 核心循环不因新增图片、机关或关卡而继续膨胀；
- 所有运行日志、快照和存档写入 `user://`，不写入仓库资源目录。
