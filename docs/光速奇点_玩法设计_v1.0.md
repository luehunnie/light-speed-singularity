# 1. 游戏概述

《光速奇点》是一款固定网格上的光学解谜游戏。

玩家不能移动角色，也不能自由移动关卡中的主发射器。每个关卡预先配置玩家可以使用的机关种类、数量、可放置区域、运行期移动次数和目标。玩家通过画面下方的机关栏拿取机关，在关卡网格中放置、移动、回收并配置机关，再使用光线或光粒完成目标。

项目包含两种光形态：

- **光线**：按当前稳定布局同步计算完整路径，路径默认显示约 1 秒后消失；
- **光粒**：作为持续存在的逻辑实体，按整数 Tick 逐格移动，不留下永久轨迹。

两种形态使用统一的发射入口和交互协议，但传播算法、时间模型、视觉生命周期和结束条件彼此独立。

# 2. 固定网格规则

## 2.1 逻辑坐标

- 所有玩法位置使用 `Vector2i`；
- 一个逻辑格对应 `64×64` 世界像素（逻辑格尺寸，不是光线/光粒可见尺寸；光视觉尺寸见 §5.2.1）；
- 格子中心位于 `(32 + 64x, 32 + 64y)`；
- 1920×1080 窗口分辨率不改变逻辑格尺寸；
- 关卡物件的 `cell` 是唯一逻辑位置事实；
- 世界像素位置只负责显示。

## 2.2 编辑器格子吸附

关卡固定对象必须支持在 Godot 编辑器中：

```text
拖动对象
→ 自动换算最近逻辑格
→ 吸附到64格中心
→ 回写cell
```

张梓涵可以在 2D 编辑界面拖动、复制、放置对象，但对象不得停留在非网格位置。

复制对象后，副本仍应：

- 具备独立场景实例；
- 自动吸附；
- 在关卡加载时接受重复、越界和占用校验；
- 不依赖手工修改核心脚本。

实施状态说明（目标关卡编辑体验）：

- `GridPlacedObject` 基础与位置契约已实现：`position` 为场景编辑事实，`cell` 由 `position` 派生，`cell↔position` 换算边界已建立（D3A 不再标记为待重构）；
- 已完成：编辑器方法 B（2D 视图拖动、64×64 吸附、写回逻辑 `cell`）与正式关卡模板（四层 `TileMapLayer`）已由 D5 落地；`LevelValidator` v0 只读结构化校验器已由 D6 实现；
- Godot 原生 GUI 关卡编辑基础（拖动、复制、吸附、`position` 的 Undo/Redo）已完成；墙体四视觉轴（─ │ / \）方向编辑已完成，四轴在 gameplay 上完全等价；
- 仍属目标、尚未实现：完整多格对象编辑流程、Runtime 自动 Validation Gate（运行期自动调用校验器）；
- 上述拖动吸附流程描述的是目标玩法和关卡编辑体验，已落地部分以真实代码为准。

## 2.3 地图与对象的编辑方式

适合使用 `TileMapLayer` 绘制：

- 地面；
- 普通墙体；
- 可放置区域；
- 禁止放置区域；
- 地图形状；
- 装饰图块。

适合使用可拖动场景对象：

- 发射器；
- 水晶；
- 预置镜面；
- 分光器；
- 滤光片；
- 转换器；
- 检测器；
- 受控机关；
- 教学标记。

# 3. 玩家核心循环

## 3.1 布置

玩家进入关卡后可以：

- 观察地图和目标；
- 查看本关机关栏和剩余数量；
- 从机关栏拿取新机关；
- 首次放置机关；
- 移动已经放置的玩家机关；
- 将玩家机关拖回机关栏回收；
- 修改镜面朝向、转换器方向等人工配置；
- 查看运行期移动次数；
- 查看发射器当前光形态和方向；
- 在关卡规则允许时调整主发射器八方向朝向；
- 在关卡规则允许时切换主发射器 RAY / PARTICLE 初始光形态。

## 3.2 开始运行确认

> 实施状态说明：本节是冻结的目标玩法。READY_TO_FIRE 和开始运行按钮尚未实现。当前主场景仍可按现有四状态逻辑直接运行。后续实施不能破坏当前行为保持式迁移。
>
> 补充：READY_TO_FIRE / 开始运行门属于目标设计，不是当前 `RunStateController` 的第五状态；当前运行状态仍为四状态（SETUP、PULSE_ACTIVE、MOVE_WINDOW、COMPLETED）。

为防止玩家误按 Space，关卡初始不能直接发射。

流程：

```text
SETUP
→ 玩家点击“开始运行”
→ READY_TO_FIRE
→ 玩家按 Space 发射
```

规则：

- “开始运行”按钮本身不发射；
- 玩家只需在一次运行开始时点击一次；
- 进入 `READY_TO_FIRE` 后，后续 `MOVE_WINDOW` 中不必再次点击；
- R 重置后回到 `SETUP`，必须重新点击；
- 点击开始运行后，主发射器方向、主发射器初始光形态和机关内部人工配置锁定；
- 布局拿取、首次放置、移动和回收继续采用当前代码已经实现的规则；
- 关卡完成后所有交互冻结，只保留 R。

## 3.3 运行阶段的正式布局权限

当前代码行为正式成为玩法基准。

除 `COMPLETED` 外：

- 可以从机关栏拿取新机关；
- 可以首次放置；
- 可以移动已有机关；
- 可以回收已有机关；
- 可以取消或回滚非法拖拽。

进入运行后禁止：

- 修改镜面朝向；
- 修改转换器、分光器等内部配置；
- 修改主发射器方向；
- 切换主发射器初始光形态；
- 直接修改关卡预置对象。

运行期成功移动已放置机关到另一个合法格时，按照关卡配置扣除移动次数。首次放置、回收、非法目标、原格松手和取消不扣当前“直接移动次数”。

运行期回收后重新从库存放置不计入直接移动次数，是当前已知边界。后续完整版本可通过机关身份跨库存事务进一步完善，但不得通过禁止回收来掩盖问题。

当前实现基线（真实代码）：

```text

```

目标最小状态：

```text
SETUP
READY_TO_FIRE
PULSE_ACTIVE
MOVE_WINDOW
COMPLETED
```

| 状态 | 布局编辑 | 配置编辑 | Space | 开始按钮 | R |
|---|---:|---:|---:|---:|---:|
| `SETUP` | 允许 | 允许 | 禁止 | 可用 | 允许 |
| `READY_TO_FIRE` | 允许 | 禁止 | 允许 | 禁用或隐藏 | 允许 |
| `PULSE_ACTIVE` | 允许 | 禁止 | 禁止 | 禁用或隐藏 | 允许 |
| `MOVE_WINDOW` | 允许 | 禁止 | 允许 | 禁用或隐藏 | 允许 |
| `COMPLETED` | 禁止 | 禁止 | 禁止 | 禁用 | 允许 |

# 5. 发射器

## 5.1 固定规则

- 主发射器是关卡固定对象；
- 玩家不能整体移动发射器；
- 玩家不能整体移动主发射器是玩法规则；在编辑器中配置发射器的初始位置、方向和光形态属于关卡制作层面，与运行期玩法不可移动是不同层面，二者不是同一件事；
- 主发射器最终目标支持八方向：UP / UP_RIGHT / RIGHT / DOWN_RIGHT / DOWN / DOWN_LEFT / LEFT / UP_LEFT，RAY 与 PARTICLE 两种光形态一致；
- 在 `SETUP` 中，玩家可以调整主发射器八方向朝向；
- 方向配置在开始运行后锁定；
- PARTICLE 从主发射器发射时默认速度为**标准**；
- 发射器通过统一发射请求描述当前位置、方向和光形态；
- 发射器不直接执行传播。
- 实施状态：当前真实代码 Ray 已支持八方向；Particle 仍为四正方向（RIGHT/DOWN/LEFT/UP）且未接运行时，Particle 八方向属最终目标、尚未实现。

## 5.2 视觉

同一种光形态使用一张基础朝向图片，通过旋转视觉子节点显示八个方向。

- 不旋转发射器逻辑根节点；
- 光线发射器和光粒发射器使用不同外观；
- 切换光形态时切换对应视觉；
- 方向和光形态是逻辑事实，图片不能反向决定玩法状态。

### 5.2.1 光视觉尺寸（冻结）

> 本规格是当前正式目标规格，不是临时建议。

- 逻辑格 = `64×64` 世界像素（见 §2.1）；
- 光线（RAY）可见光束厚度 = `16px`：水平 Ray 高 16px、垂直 Ray 宽 16px、对角 Ray 沿传播法线方向厚度 16px；
- 光粒（PARTICLE）可见主体 = **沿传播方向长 `24px`、横向宽 `16px`**；
- 光粒主体跟随八方向传播方向旋转；
- glow / halo / 尾迹允许超出主体尺寸；
- glow / halo / 尾迹不参与逻辑传播判定；
- 视觉尺寸不改变 `Vector2i` 传播和格子判定；
- 不修改 `GridMetrics`；
- 不引入像素级物理碰撞作为核心判定。

## 5.3 光形态切换

关卡可决定：

- 固定使用光线；
- 固定使用光粒；
- 允许玩家在布置阶段切换；
- 通过形态转换器在传播过程中改变。

规则：

- 若关卡允许玩家切换主发射器初始光形态，使用 `Q` 在 RAY / PARTICLE 间切换；
- 仅 `SETUP` 阶段允许切换主发射器初始光形态；
- 若关卡固定光形态，则 `Q` 不改变形态；
- 开始运行后，主发射器初始光形态锁定；
- 形态转换器仍可按照自身规则处理传播中的光。

## 5.4 主发射器操作按键（冻结）

| 功能 | 默认按键 |
|---|---|
| 上 | `W` / `↑` |
| 下 | `S` / `↓` |
| 左 | `A` / `←` |
| 右 | `D` / `→` |
| 右上 | `W+D` / `↑+→` |
| 右下 | `S+D` / `↓+→` |
| 左下 | `S+A` / `↓+←` |
| 左上 | `W+A` / `↑+←` |
| 切换 RAY / PARTICLE | `Q`（仅关卡允许且处于 SETUP 时有效） |
| 发射 | `Space` |
| 完整重置 | `R` |

按键规则：

- 八方向输入直接指定目标朝向，不采用“每按一次旋转 45°”作为默认交互；
- 相反方向同时按下不产生有效斜向；
- `Space` 是否允许由运行状态决定；
- `R` 始终执行完整关卡重置，不承担镜面旋转或其他局部功能。

## 5.5 实施状态说明

> 区分冻结规则与当前实现。

已实现：

- `EmitterConfigNode` 负责发射器在编辑器中的配置（位置、方向、光形态）；
- `EmissionPreview` 提供发射预览；
- 真实光线运行接线已有基础，可基于当前布局发射并计算光路。

当前主要停留在配置与预览边界：

- 光粒（PARTICLE）形态当前主要停留在配置与预览边界，尚未形成完整运行系统。

尚未实现：

- 玩家对主发射器的八方向实时调向输入（按键方案已冻结为 §5.4）；
- 光线/光粒形态切换（`Q` 已冻结，关卡可决定是否允许）；
- 对应提示 UI。

`EmissionPreview` 是配置期预览，不是正式运行光线，不得当成运行光路。

# 6. 光线

- 支持八方向传播；
- 主发射器最终目标从八方向发射（UP/UP_RIGHT/RIGHT/DOWN_RIGHT/DOWN/DOWN_LEFT/LEFT/UP_LEFT）；当前真实代码 Ray 已支持八方向；
- 镜面等机关可以把光线反射到八方向；
- 按当前稳定布局同步计算完整路径；
- 路径默认显示约 1 秒；
- 路径视觉消失不代表普通独立水晶熄灭；
- 下一次发射重新读取当前布局；
- 使用最大步数、重复状态或最大状态数防止无限循环；
- 颜色只属于光线。

颜色完整版本保留：

- 白；
- 红；
- 绿；
- 蓝。

滤光规则完整版本保留：

- 白光经过滤光片变为对应单色；
- 同色光保持；
- 异色光被吸收；
- 不制作 RGB 混色。

实施状态说明：

- 已冻结设计：八方向传播、瞬时计算、路径约 1 秒清理、白光与 RGB 颜色规则、滤光规则；
- 已实现：基础光线运行接线（八方向、瞬时传播、路径显示与约 1 秒清理）；
- 尚未实现：完整颜色与滤光系统的全量落地。

# 7. 光粒

> 实施状态说明：本节是已冻结的目标玩法设计。当前光粒主要停留在配置与预览边界，完整光粒运行系统尚未实现，不得写成已完成。
>
> 已冻结设计：八方向发射（最终目标 UP/UP_RIGHT/RIGHT/DOWN_RIGHT/DOWN/DOWN_LEFT/LEFT/UP_LEFT；当前真实代码 Particle 仍为四正方向 RIGHT/DOWN/LEFT/UP，Particle 八方向尚未实现）、整数 Tick 逐格传播、三档离散速度、正交/斜向速度换算、反射可遵守八方向结果、光粒不可变色。
> 尚未实现：完整光粒执行模块、Particle 八方向、速度档位机关、运行期安全批次提交。

- 按整数 Tick 逐格传播；
- 基础逻辑时间：`1 Tick ≈ 0.1 秒`；
- 不留下永久轨迹；
- 主发射器最终目标从八方向发射；
- 主发射器发出的 PARTICLE 默认从**标准速度**开始；
- 镜面可以按照规则产生八方向反射；
- 支持慢速、标准、快速三个离散档位；
- 加速器提升一档；
- 减速器降低一档；
- 不超过最高档，不低于最低档；
- 运行期布局提交只影响尚未经过的后续路径；
- 不回溯已经完成的事件；
- 颜色系统不作用于光粒。

### 7.1 三档速度（冻结）

正交方向 `↑ ↓ ← →`：

| 档位 | 每移动 1 格 | 约合时间 |
|---|---:|---:|
| 慢速 | 8 Tick | 0.8 秒 |
| 标准 | 4 Tick | 0.4 秒 |
| 快速 | 2 Tick | 0.2 秒 |

斜向方向 `↗ ↘ ↙ ↖`：

| 档位 | 每移动 1 个斜向格 | 约合时间 |
|---|---:|---:|
| 慢速 | 11 Tick | 1.1 秒 |
| 标准 | 6 Tick | 0.6 秒 |
| 快速 | 3 Tick | 0.3 秒 |

斜向值是对同速下 `√2` 距离差的整数 Tick 近似。方向变化不改变速度档位；正交/斜向切换只改变下一传播步使用的 Tick 数。

### 7.2 速度变化生效时机

当机关改变光粒速度时：

1. 光粒先按进入该格前的速度完成到达；
2. 机关读取当前档位并计算新档位；
3. 新档位从机关之后的下一传播步开始生效；
4. 不回溯已经完成的移动时间。

# 8. 机关栏与拖拽

每关分别配置：

- 机关种类；
- 每种机关总数；
- 是否可由玩家放置；
- 是否允许在运行期移动；
- 占用格；
- 可放置区域规则。

拖拽流程：

```text
按住左键拿取
→ 显示预览
→ 自动吸附逻辑格
→ 合法性反馈
→ 松手二次校验
→ 成功提交或完整回滚
```

规则：

- 预览不等于正式占用；
- 未成功放置前不扣库存；
- 非法放置不改变库存与占用；
- 已放置机关移动失败必须回原格；
- 拖回机关栏是回收；
- 合法性判定统一采用“允许区域 + 阻挡/占用查询”，各机关不自行维护判定副本；
- 回收失败时保持机关、库存和占用三者一致，不在玩法层展开内部提交与注册顺序；
- UI 区域不得点击穿透；
- 多格机关使用锚点格和占用偏移；
- 占用更新必须原子提交或回滚。

### 9.1.1 光屏障 P0 核心规则

光屏障为关卡预置固定场景条件，不进入玩家机关栏。

- 关卡编辑者可按八方向配置其穿越轴；
- 只有与穿越轴完全共线的两个相反方向进入穿越判定；
- 其余六个方向一律阻挡；
- RAY 无法通过；
- 慢速 PARTICLE 无法通过；
- 标准 PARTICLE 可通过，通过后降为慢速；
- 快速 PARTICLE 可通过，通过后降为标准；
- 屏障沿切线方向两侧必须配置固定普通墙，缺少任一侧视为非法关卡配置。

详细边界以独立《机关规则：光屏障》为准。

# 10. 水晶与通关

## 10.1 基础独立水晶

- **任何合法到达的光都可以点亮基础水晶**；
- 不检查 RAY / PARTICLE 光形态；
- 不检查光线颜色；
- 不检查光粒速度；
- 合法命中后点亮；
- 光线路径消失或光粒离开后仍保持；
- 只在 R 或关卡重置时恢复；
- 未点亮与点亮必须有清晰视觉差异。

## 10.2 完整复合条件

水晶允许配置多种附加条件，包括：

- 所需光形态；
- 所需光线颜色；
- 是否属于组；
- 组 ID；
- 顺序编号；
- 完成窗口；
- 是否为必需目标。

启用的多个条件之间使用“并且（AND）”。

当前阶段讨论某一种条件时，主要展开该条件本身；其他可组合条件只保留兼容性说明，不要求在同一规则讨论中全部展开。

## 10.3 同时组和顺序组

完整设计保留：

- 第一颗合法成员点亮时启动固定窗口；
- 后续触发不刷新窗口；
- 窗口内完成后整组保持到 R；
- 窗口到期未完成则整组清除；
- 顺序错误或同一逻辑时刻触发多个不同序号时清除进度。

## 10.4 通关

所有本关必需目标满足后：

- 进入 `COMPLETED`；
- 冻结拿取、放置、移动、回收、配置和发射；
- 显示通关结果；
- 允许 R 或进入后续流程。

# 13. 重置

R 是完整运行重置，不只是清光路。

至少恢复：

- 取消拖拽和预览；
- 清理当前光执行；
- 使旧异步回调失效；
- 清光路或光粒；
- 重置目标；
- 清除完成状态；
- 清理玩家机关和动态占用；
- 恢复库存；
- 清零运行期移动次数；
- 恢复发射器初始配置和光形态；
- 返回 `SETUP`；
- 重新要求点击“开始运行”。

关卡预置对象、静态地图和初始配置不得被误删。
