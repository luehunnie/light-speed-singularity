# 1. 总体原则

项目文件结构遵守以下原则：

1. `gameplay/` 保存可复用的游戏系统、公共协议、机关和运行模块；
2. `levels/` 保存关卡模板、单机关原型、组合原型、灰盒关卡和正式关卡；
3. `assets/` 保存美术、音频、视觉 Profile 和数据 Resource；
4. `tests/` 保存技术测试脚本和测试场景；
5. `docs/` 保存正式文档、API、操作指南和本地 AI 协作文档；
6. `user://` 保存运行时生成的日志、状态快照和存档，不进入 Git；
7. 核心运行控制器只负责引用、信号连接和生命周期协调；
8. 光线、光粒、库存、拖拽、目标、日志和自检必须分别放入独立模块；
9. 新增机关、光形态、目标或关卡时，原则上不得修改核心循环；
10. 现有代码采用行为保持式迁移，不推倒重写；
11. 目录与文件规模控制：本文档是文件结构权威。源码文件物理行 `<250` 正常职责检查、`≥250` 强制职责复查、`≥350` 强制拆分评估；普通职责目录推荐 `≤6` 主要源码文件、`7～8` 关注职责密度、`>8` 必查是否拆分子职责；不机械拆分，不得删必要中文注释压行数；`.gd.uid` 不计入目录源码数量；不得为减少文件数制造巨型脚本。

## 5.1 `level_runtime_controller.gd`

当前真实路径为 `gameplay/runtime/level_runtime_controller.gd`（`extends Node`，D3-E 已实现并接入 `core_loop_prototype`），完整拥有普通脉冲发射请求编排、异步脉冲结束、`pulse_generation` 过期保护、运行期移动次数与 R 完整重置顺序。状态事实仍由 `RunStateController` 唯一持有；完成事实由 `ObjectiveController` 唯一提供；光路视觉由 `LightVisualController` 拥有；拖拽业务由 `DragFlowController` 拥有。

负责：

- 保存必要模块引用；
- 初始化和依赖校验；
- 连接信号；
- 接收发射请求（`request_fire`）与 R 重置请求（`reset_runtime`）；
- 逐 step 先视觉后水晶应用传播结果；
- 异步脉冲结束与 `pulse_generation` 过期保护；
- 运行期移动次数扣除与查询；
- 协调完整重置顺序。

不负责：

- 光线路径逐格计算（由 `RayExecutionModule`）；
- 光粒 Tick；
- 镜面反射；
- 库存数量（由 `InventoryController`）；
- 鼠标拖拽事务（由 `DragFlowController`）；
- UI细节；
- 日志文件写入；
- 具体水晶激活（由 `ObjectiveController`）。

# 6. `gameplay/grid/`：网格基础

目标文件（`grid_placed_object.gd` 已实现位置契约；网格坐标换算已落地为 `grid_coordinate_rules.gd`）：

```text

├─ grid_coordinate_rules.gd      # 已实现：cell↔world 纯换算唯一来源
└─ grid_placed_object.gd          # 已实现：position 为事实，cell 派生
```

## 6.1 `grid_metrics.gd`

只保存：

- `CELL_SIZE = 64`；
- `HALF_CELL_SIZE = 32`；
- 单格世界尺寸；
- 通用格子和世界坐标换算函数。

不保存地图、机关和关卡状态。

## 6.2 `grid_placed_object.gd`

当前已实现（`@tool`，`class_name GridPlacedObject`，`extends Node2D`）。位置契约：

- `position` 是场景编辑事实（由 Godot 原生拖动、复制、64×64 网格吸附与 position Undo/Redo 负责）；
- `cell` 为计算属性，由 `position` 派生（`GridCoordinateRules.world_to_cell`），不是编辑事实，不序列化到 `.tscn`；
- `set_cell` 通过 `cell_to_world` 写回 `position`；
- 多格占用偏移接口已冻结（`get_occupied_offsets(p_orientation: int = 0)` / `get_occupied_cells(anchor_cell: Vector2i, p_orientation: int = 0)`）：`anchor_cell` 为查询参数或由根 `position` 派生，不是持久化第二位置事实；`p_orientation` 为中性方向槽（默认 0），不是全局方向枚举；具体多格子类尚未实现；
- 不引用玩法对象、Registry、Validator、世界查询或核心循环；不做地图边界、占用登记或合法性校验。

`cell`↔`world` 纯换算唯一来源为 `gameplay/grid/grid_coordinate_rules.gd`（`cell_to_world` / `world_to_cell`，`cell_to_world(Vector2i.ZERO)` 在 64 格下为 `(32, 32)`，即从 64×64 格子左上角计算的格中心偏移，非根节点局部原点）。`GridPlacedObject` 根节点自身局部原点为 `(0, 0)`，根 `position` 对齐目标格中心；visual、collision、hint 子节点使用相对根节点的局部坐标，不得把子节点统一放到 `(32, 32)` 二次补偿；多格对象根 `position` 对齐明确锚点格中心。

发射器、水晶、预置机关继承或组合这个能力（`EmitterConfigNode`、`BasicCrystal` 均继承 `GridPlacedObject`）。Godot 原生负责节点拖动、复制、64×64 网格吸附和 position Undo/Redo，项目不开发正式的移动/吸附编辑器插件。

# 当前真实调度链

当前原型协调仍由 `core_loop_prototype.gd` 承担，但大量运行期职责已迁出为独立模块，包含：

- 当前四状态：`SETUP` / `PULSE_ACTIVE` / `MOVE_WINDOW` / `COMPLETED`；
- 运行状态所有权已迁出核心：`RunStateController`（`gameplay/interaction/run_state_controller.gd`）持有唯一运行状态，核心通过 `begin_pulse()`、`finish_pulse()`、`reset_to_setup()` 请求转换；
- 运行期编排已迁出核心：`LevelRuntimeController`（`gameplay/runtime/level_runtime_controller.gd`）唯一持有 `pulse_generation`、`runtime_moves_used`、发射编排、异步过期保护与 R 完整重置顺序；
- 拖拽业务已迁出核心：`DragFlowController` 完整拥有一次拖拽生命周期，`DragContext` 保存纯临时事实，`PlayerInteractionController` 分类输入；
- 放置与库存已迁出核心：`PlacementController`（玩家机关映射/ID/原子事务）、`InventoryController`（total/remaining 与归还预留）、`OccupancyRegistry`（占用事实与原子单格移动）；
- 世界查询已迁出核心：`LevelWorldQuery`、`LightWorldQuery`、`RayMechanismAdapter`、`RayExecutionModule`、`FireRequest`、`FixedEmitter`；
- 视觉已迁出核心：`LightVisualController` 拥有普通光路视觉节点集合；
- 水晶与目标已迁出核心：`BasicCrystal` 显式 `crystal_id`，`LevelObjectRegistry` 双向索引，`ObjectiveController` 负责激活/完成/重置；
- 当前 Diagnostics 启动自检链（见 §18.2），编排由 `StartupSelfCheckCoordinator` 整块承担。

`GridPlacedObject` 位置契约（`position` 为场景编辑事实，`cell` 由 `world_to_cell` 派生，`set_cell` 用 `cell_to_world`）、`EmitterConfigNode`、`EmissionPreview`、`LightPathLayer` 与 `RuntimeObjects/Emitter` 结构已实现。`LevelValidator` v0（D6）、编辑器方法 B 单格（2D 视图直接拖动编辑与位置写回）、Godot 原生 GUI 关卡编辑基础、墙体方向编辑已实现；统一 `EmissionRequest` / `LightRuntimeCoordinator` / 光粒运行时、`READY_TO_FIRE` 与开始运行入口、Runtime 自动 Validation Gate、方法 B 多格编辑均未实现。Godot 原生负责节点拖动、复制、64×64 网格吸附和 position Undo/Redo，项目不开发正式的移动/吸附编辑器插件；`addons/light_speed_art_profile/` 是唯一正式插件，不进入运行时依赖链。

# 35. 调度链九：日志、自检与快照

本节为混合章节：同时记录当前已经实现的 Diagnostics 自检/日志链，以及未来尚未实现的 Debug 控制台和真实玩法快照采样目标。不要把整节视为未实现。

## 当前已实现

- `core_loop_prototype._ready()`（仅 Debug 构建）采集网格采样格与库存一致性只读快照，调用 `StartupSelfCheckCoordinator.run_all(...)`；
- 协调器按固定顺序构建并执行七项 `SelfCheckCallable`；
- 每项调用 `DiagnosticsController.run_self_check()`；
- 每次临时创建 `SelfCheckRunner`；
- 七项全部成功后写一条 INFO 摘要；
- `RuntimeLogger` 写入 `user://diagnostics/logs/runtime.log`；
- `RuntimeLogger` 不输出 Godot 控制台；
- `RuntimeSnapshotData`、序列化、写入结果和文件保存能力已实现。

当前真实启动自检链：

```text
core_loop_prototype._ready()（仅 Debug 构建）
→ 采集网格采样格与库存一致性只读快照
→ StartupSelfCheckCoordinator.run_all(...)
→ 协调器按固定顺序构建并执行七项 SelfCheckCallable
→ 每项调用 DiagnosticsController.run_self_check()
→ 每次临时创建 SelfCheckRunner
→ 七项全部成功
→ 写一条 INFO 摘要到 user://diagnostics/logs/runtime.log
```

RuntimeLogger 不输出 Godot 控制台。七项自检编排已由 `StartupSelfCheckCoordinator` 整块承担，不再由核心内联编排。

日志落盘链（`RuntimeLogger` 已实现；“输入log”触发属目标 Debug 控制台，尚未实现）：

```text
各模块调用RuntimeLogger公共接口
→ 写入内存缓冲
→ 达到落盘条件或输入log
→ 保存到user://diagnostics/logs/
→ 检查单文件、文件数和总容量
→ 删除最旧文件
```

## 目标 / 尚未实现

- 游戏内 Debug 输入；
- `log` / `check` / `state` / `clearlog` 命令；
- 由各玩法模块自动生成完整快照；
- 真实玩法状态自动采样；
- 通过各模块 `build_debug_snapshot()` 聚合真实状态。

目标 / 尚未实现：Debug 输入与真实玩法自动采样链：

```text
输入state/log
→ RuntimeSnapshot
→ 各模块build_debug_snapshot()
→ 生成JSON
→ 保存到snapshots/
→ 删除超限旧快照
```

该箭头链仅为目标方向，当前未接线：游戏内 `input state/log`、各模块 `build_debug_snapshot()` 与自动生成完整玩法 JSON 均尚未实现。

# 41. 最终验收标准

这套文件结构完成后，应满足：

- 核心循环只保留协调职责；
- 光线与光粒独立；
- 发射器只生成通用请求；
- 传播只通过世界查询读取关卡；
- 关卡制作不修改核心代码；
- 美术通过 Profile 替换；
- 固定对象可在 Godot 中拖动、复制和吸附；
- 技术测试和关卡原型分离；
- 日志不会无限增长；
- 新增机关不要求修改核心循环；
- 当前已完成代码被迁移复用，而不是重新实现；
- 每个文件都能明确回答“为什么放在这里”。
