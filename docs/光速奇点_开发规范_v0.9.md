# 《光速奇点》开发规范

> 版本：v0.9
> 更新日期：2026 年 7 月 22 日
> 状态：模块解耦、行为保持式迁移与诊断规范冻结稿
> 本文规定代码、模块、场景、资源、测试、Git和AI协作规范；技术选型见《光速奇点_技术栈_v0.9》。

---

# 1. 总原则

## 1.1 核心原则

1. 核心循环不得包含具体光形态实现。
2. 核心循环只保留初始化、依赖校验、信号连接、生命周期协调、全局状态切换和重置入口。
3. 发射器只生成统一发射请求。
4. 光运行协调器根据光形态选择对应执行模块。
5. 光线和光粒共享协议，不强行共享具体算法。
6. 核心循环只依赖稳定公共接口，不直接引用具体机关和视觉节点。
7. 模块内部状态只能通过公共方法修改。
8. 跨模块结果优先使用信号、不可变结果对象或明确返回值。
9. 光传播模块只依赖只读世界查询接口。
10. 水晶和机关通过统一交互事件接收传播结果。
11. 逻辑传播与视觉显示分离。
12. 新增机关、光形态和目标原则上不修改核心循环。
13. 不创建包办全部职责的巨型 `GameManager`、`VisualManager` 或全局事件总线。
14. 架构冻结的是公共契约，不是内部每一行实现。

## 1.2 行为保持式迁移

现有代码不得推倒重写。

迁移流程：

```text
记录当前行为
→ 为现有逻辑建立公共接口
→ 原函数或等价逻辑迁入对应模块
→ 核心循环改为引用模块
→ 自动检查
→ 人工回归
→ 合并
→ 再抽离下一职责
```

必须复用当前已经验证的：

- `GridMetrics`；
- `OccupancyRegistry`；
- `PlaceableToken`；
- 单格镜面反射；
- `BasicCrystal`；
- `ObjectVisualView` 和视觉 Profile；
- `InventorySlotView`；
- `LightSegmentView`；
- 当前拖拽、移动、回收和回滚；
- 当前运行状态与权限；
- 当前移动次数计算；
- 当前 R 完整重置；
- 当前普通光线传播算法和安全上限；
- 当前启动期自检。

禁止先删除旧实现再整体重写。

# 2. 模块职责规范

## 2.1 单一职责

每个模块必须明确：

- 负责什么；
- 输入是什么；
- 输出是什么；
- 修改哪些状态；
- 发出哪些信号；
- 不负责什么。

## 2.2 核心循环

允许：

- 保存模块引用；
- 校验依赖；
- 连接信号；
- 接收开始运行、发射、重置等高层请求；
- 协调运行状态；
- 接收统一执行结果；
- 请求目标判断；
- 协调完整重置。

禁止：

- 逐格计算光线路径；
- 推进光粒 Tick；
- 直接判断镜面；
- 直接激活水晶；
- 管理库存数量；
- 处理鼠标拖拽事务；
- 创建具体光路纹理；
- 直接读写占用表内部字典；
- 写入日志文件；
- 保存具体关卡对象数组。

## 2.3 模块引用

正确：

```gdscript
inventory_controller.commit_take(item_id)
run_state_controller.enter_execution()
light_runtime.execute(request)
```

错误：

```gdscript
inventory_controller.remaining -= 1
run_state_controller.current_state = RunState.PULSE_ACTIVE
particle_module.active_particles.clear()
```

引用其他模块时只能调用公开契约，不得直接修改内部字段。

## 2.4 依赖方向

推荐：

```text
核心协调层
→ 公共协议和控制器
→ 具体玩法模块
→ 基础网格、资源与数据
```

禁止：

- 基础网格依赖核心循环；
- 视觉组件修改传播逻辑；
- 传播模块直接操作UI；
- 机关脚本直接修改库存；
- 关卡场景脚本修改全局存档内部结构；
- 诊断模块修改被检查模块状态。

# 3. GDScript规范

## 3.1 静态类型

- 公共函数必须写参数类型；
- 公共函数必须写返回类型；
- 重要局部变量写类型；
- 使用稳定类型对象代替结构任意变化的 Dictionary；
- `Dictionary` 只用于清楚、局部、可验证的数据场景；
- 禁止依赖隐式类型造成跨模块不确定性。

## 3.2 中文注释

每个模块顶部必须说明：

- 模块职责；
- 系统位置；
- 主要依赖；
- 明确不负责的内容。

每个新增或修改函数使用中文 `##` 文档注释，说明：

- 职责；
- 输入；
- 输出；
- 副作用；
- 边界和停止条件。

关键逻辑必须有中文行内注释：

- Tick 批次；
- 原子提交和回滚；
- 脉冲版本失效；
- 状态窗口；
- 移动次数扣除；
- 占用更新；
- 方向映射；
- 编辑器吸附；
- 日志轮转；
- R 重置。

禁止无信息价值的逐行复述。

## 3.3 命名

- 类名：`PascalCase`；
- 文件：`snake_case.gd`；
- 私有字段和函数：以下划线开头；
- 稳定状态ID：小写英文 `StringName`；
- 布尔值使用 `is_`、`has_`、`can_`；
- 请求使用 `request_`；
- 提交使用 `commit_`；
- 校验使用 `validate_`；
- 重置使用 `reset_`。

# 4. 场景与节点规范

## 4.1 可复用对象

每种机关、发射器、水晶和视觉组件使用独立 `.tscn`，不在正式关卡中手工拼接其内部结构。

## 4.2 固定节点契约

被脚本依赖的核心子节点名称不得随意修改。修改前必须：

- 搜索全部引用；
- 更新场景和脚本；
- 运行场景；
- 记录接口变更。

## 4.3 编辑器格子对象

所有固定关卡对象继承或组合 `GridPlacedObject`：

- `cell` 是唯一逻辑事实；
- Inspector 修改 `cell` 同步世界位置；
- 编辑器拖动后吸附并回写 `cell`；
- 多格对象使用占用偏移；
- 不允许子类建立第二套逻辑位置。

## 4.4 TileMapLayer

静态地图使用分层 TileMapLayer。图块自定义数据命名稳定，不在多个脚本中复制解释。

# 5. 资源与视觉规范

## 5.1 视觉资源

- 代码不写死图片路径；
- 使用 `.tres` Profile 配置纹理；
- 世界对象和 UI 图标分离；
- 世界单格素材以64×64画布为基础；
- 使用 Nearest 过滤；
- 内容居中；
- 正常纹理默认不使用旧占位颜色染色；
- 合法、非法、禁用反馈使用独立覆盖层或调制接口。

## 5.2 视觉与逻辑分离

视觉不得决定：

- 镜面方向；
- 水晶是否点亮；
- 发射器光形态；
- 机关占用；
- 光传播结果。

逻辑状态通过稳定状态ID驱动视觉。

# 6. 光执行规范

## 6.1 通用请求

发射器生成统一 `EmissionRequest`，至少包含：

- 来源ID；
- 起始格；
- 方向；
- 光形态；
- 执行编号；
- 后续需要时包含颜色。

## 6.2 通用协调

`LightRuntimeCoordinator`：

- 接收请求；
- 选择已注册执行模块；
- 防止重复执行；
- 转发开始、交互、完成和失败；
- 取消当前执行；
- 不计算具体传播。

## 6.3 只读世界查询

传播模块只通过 `LightWorldQuery` 查询：

- 地图边界；
- 阻挡；
- 交互对象；
- 目标；
- 当前光形态是否可通过。

查询接口不得删除墙、移动机关或修改目标。

## 6.4 光线和光粒

共享：

- 发射请求；
- 光形态；
- 交互事件；
- 执行结果；
- 世界查询；
- 开始、完成、失败信号。

独立：

- 算法；
- 时间模型；
- 路径或实体状态；
- 视觉生命周期；
- 稳定判定；
- 终止条件。

# 7. 放置与库存规范

## 7.1 放置事务

正式提交顺序：

```text
接收玩家意图
→ 校验权限
→ 校验目标格
→ 校验占用
→ 预备修改
→ 原子提交
→ 成功后更新库存和UI
→ 失败时完整回滚
```

## 7.2 占用表

`OccupancyRegistry` 只负责：

- 格到机关ID；
- 机关ID到占用格；
- 登记；
- 注销；
- 查询；
- 一致性检查。

不负责：

- 鼠标；
- UI；
- 地图合法区；
- 运行状态；
- 库存；
- 传播；
- 通关。

## 7.3 库存

库存模块负责：

- 总量；
- 剩余；
- 成功放置扣除；
- 回收归还；
- 重置；
- 一致性。

玩家交互模块不得直接修改库存内部字段。

# 8. 诊断、日志与自检

源代码放在：

```text
gameplay/diagnostics/
```

技术测试放在：

```text
tests/
```

运行生成文件放在：

```text
user://diagnostics/
```

## 8.1 模块内部自检

每个模块公开只读检查方法，例如：

```text
validate_consistency()
validate_state()
build_debug_snapshot()
```

模块自己负责判断本模块不变量。

## 8.2 自检协调器

`SelfCheckRunner` 只负责：

- 调用各模块公开检查；
- 收集结果；
- 输出摘要；
- 不读取内部私有字段；
- 不修复状态。

## 8.3 日志

日志必须结构化：

```text
[时间][等级][模块][执行ID] 消息
```

等级：

- DEBUG；
- INFO；
- WARN；
- ERROR。

禁止每帧、每次鼠标移动或无状态变化时刷日志。

## 8.4 日志轮转与删除

默认值：

- 单个日志文件最大 `2 MiB`；
- 最多保留 `8` 个日志文件；
- 日志目录总量上限 `16 MiB`；
- 单个状态快照最大 `1 MiB`；
- 最多保留 `10` 个快照；
- 快照目录总量上限 `10 MiB`。

超过任意限制：

```text
按修改时间从旧到新排序
→ 删除最旧文件
→ 重新计算数量和容量
→ 直到全部满足
```

清理失败必须记录警告，但不得阻塞游戏主流程。

Debug版：

- 完整日志；
- 自检；
- 调试控制台；
- JSON快照。

Release版：

- 默认只保留 ERROR 和必要启动信息；
- 不开放调试控制台；
- 不输出高频调试日志。

## 8.5 调试命令

Debug游戏内控制台可支持：

- `log`：导出日志和状态快照；
- `check`：执行跨模块自检；
- `state`：显示当前状态摘要；
- `clearlog`：清理当前会话缓冲。

不依赖外部 PowerShell 命令窗口。

# 9. 测试规范

## 9.1 三层测试

1. 模块自检；
2. 技术测试场景；
3. 人工操作回归。

MCP启动无错误不能代替鼠标、键盘和视觉测试。

## 9.2 每次抽离后的回归

至少验证：

- 主场景启动；
- 开始运行按钮；
- Space；
- R；
- 拖拽；
- 合法和非法放置；
- 移动；
- 回收；
- 镜面；
- 水晶；
- 光路；
- 状态权限；
- 库存；
- 占用一致性；
- 无新错误。

## 9.3 测试目录

```text
tests/
├─ unit/
├─ integration/
└─ scenes/
```

技术测试场景不进入正式选关。

# 10. Git规范

- 从最新 `main` 创建分支；
- 一个分支只做一个明确任务；
- 一次PR不混入无关重排；
- 同一时间避免多人修改同一个 `.tscn`；
- 公共接口变更先讨论；
- 至少一名队友运行或审查；
- 合并后确认 `main` 可运行；
- 删除已完成分支；
- AI 不执行 Git 写操作。

提交前：

```text
git status
git diff
git diff --check
Godot运行
人工测试
只读审查
```

# 11. AI协作规范

## 11.1 推荐分工

- GPT-5.6 Thinking：整体架构、讨论和提示词；
- GPT-5.5：本地文档、只读审计、复杂诊断；
- GLM-5.2：范围明确的实施、MCP验证和常规修复；
- 用户：人工测试、Git写操作和最终决策。

## 11.2 提示词必须包含

- 目标；
- 明确不做；
- 允许修改文件；
- 禁止修改文件；
- 完成标准；
- 自动测试；
- 人工测试；
- 停止条件；
- 中文注释要求；
- 禁止Git写操作。

## 11.3 禁止

- 一次重写整个工程；
- 未读真实代码直接生成；
- 把计划写成已完成；
- 用旧文档覆盖最新决定；
- 未运行就声称测试通过；
- 为目录整齐创建大量空模块；
- 让AI自行解决需求歧义。
