# 1. 游戏概述

《光速奇点》是一款固定网格上的光学解谜游戏。

玩家不能移动角色，也不能自由移动关卡中的主发射器。每个关卡预先配置玩家可以使用的机关种类、数量、可放置区域、运行期移动次数和目标。玩家通过画面下方的机关栏拿取机关，在关卡网格中放置、移动、回收并配置机关，再使用光线或光粒完成目标。

项目包含两种光形态：

- **光线**：按当前稳定布局同步计算完整路径，路径默认显示约 1 秒后消失；
- **光粒**：作为持续存在的逻辑实体，按整数 Tick 逐格移动，不留下永久轨迹。

两种形态使用统一的发射入口和交互协议，但传播算法、时间模型、视觉生命周期和结束条件彼此独立。

# 2. 固定网格规则

## 2.1 逻辑坐标

- 所有玩法位置使用 `Vector2i`；
- 一个逻辑格对应 `64×64` 世界像素；
- 格子中心位于 `(32 + 64x, 32 + 64y)`；
- 1920×1080 窗口分辨率不改变逻辑格尺寸；
- 关卡物件的 `cell` 是唯一逻辑位置事实；
- 世界像素位置只负责显示。

## 2.2 编辑器格子吸附

关卡固定对象必须支持在 Godot 编辑器中：

```text
拖动对象
→ 自动换算最近逻辑格
→ 吸附到64格中心
→ 回写cell
```

张梓涵可以在 2D 编辑界面拖动、复制、放置对象，但对象不得停留在非网格位置。

复制对象后，副本仍应：

- 具备独立场景实例；
- 自动吸附；
- 在关卡加载时接受重复、越界和占用校验；
- 不依赖手工修改核心脚本。

实施状态说明（目标关卡编辑体验，当前未实现）：

- 方法 A：Inspector 修改 `cell` 后同步世界位置——尚未实现；
- 方法 B：2D 编辑器拖动后吸附并回写 `cell`——尚未实现，明确延后；
- 上述拖动吸附流程描述的是目标玩法和关卡编辑体验，不代表当前编辑器已具备该能力。

## 2.3 地图与对象的编辑方式

适合使用 `TileMapLayer` 绘制：

- 地面；
- 普通墙体；
- 可放置区域；
- 禁止放置区域；
- 地图形状；
- 装饰图块。

适合使用可拖动场景对象：

- 发射器；
- 水晶；
- 预置镜面；
- 分光器；
- 滤光片；
- 转换器；
- 检测器；
- 受控机关；
- 教学标记。

# 3. 玩家核心循环

## 3.1 布置

玩家进入关卡后可以：

- 观察地图和目标；
- 查看本关机关栏和剩余数量；
- 从机关栏拿取新机关；
- 首次放置机关；
- 移动已经放置的玩家机关；
- 将玩家机关拖回机关栏回收；
- 修改镜面朝向、转换器方向等人工配置；
- 查看运行期移动次数；
- 查看发射器当前光形态和方向。

## 3.2 开始运行确认

> 实施状态说明：本节是冻结的目标玩法。READY_TO_FIRE 和开始运行按钮尚未实现。当前主场景仍可按现有四状态逻辑直接运行。后续实施不能破坏当前行为保持式迁移。

为防止玩家误按 Space，关卡初始不能直接发射。

流程：

```text
SETUP
→ 玩家点击“开始运行”
→ READY_TO_FIRE
→ 玩家按Space发射
```

规则：

- “开始运行”按钮本身不发射；
- 玩家只需在一次运行开始时点击一次；
- 进入 `READY_TO_FIRE` 后，后续 `MOVE_WINDOW` 中不必再次点击；
- R 重置后回到 `SETUP`，必须重新点击；
- 点击开始运行后，主发射器方向和机关内部人工配置锁定；
- 布局拿取、首次放置、移动和回收继续采用当前代码已经实现的规则；
- 关卡完成后所有交互冻结，只保留 R。

## 3.3 运行阶段的正式布局权限

当前代码行为正式成为玩法基准。

除 `COMPLETED` 外：

- 可以从机关栏拿取新机关；
- 可以首次放置；
- 可以移动已有机关；
- 可以回收已有机关；
- 可以取消或回滚非法拖拽。

进入运行后禁止：

- 修改镜面朝向；
- 修改转换器、分光器等内部配置；
- 修改主发射器方向；
- 直接修改关卡预置对象。

运行期成功移动已放置机关到另一个合法格时，按照关卡配置扣除移动次数。首次放置、回收、非法目标、原格松手和取消不扣当前“直接移动次数”。

运行期回收后重新从库存放置不计入直接移动次数，是当前已知边界。后续完整版本可通过机关身份跨库存事务进一步完善，但不得通过禁止回收来掩盖问题。

# 4. 运行状态

当前实现基线（真实代码）：

```text
SETUP
PULSE_ACTIVE
MOVE_WINDOW
COMPLETED
```

目标最小状态：

```text
SETUP
READY_TO_FIRE
PULSE_ACTIVE
MOVE_WINDOW
COMPLETED
```

| 状态 | 布局编辑 | 配置编辑 | Space | 开始按钮 | R |
|---|---:|---:|---:|---:|---:|
| `SETUP` | 允许 | 允许 | 禁止 | 可用 | 允许 |
| `READY_TO_FIRE` | 允许 | 禁止 | 允许 | 禁用或隐藏 | 允许 |
| `PULSE_ACTIVE` | 允许 | 禁止 | 禁止 | 禁用或隐藏 | 允许 |
| `MOVE_WINDOW` | 允许 | 禁止 | 允许 | 禁用或隐藏 | 允许 |
| `COMPLETED` | 禁止 | 禁止 | 禁止 | 禁用 | 允许 |

普通光线显示期间的布局变化不回溯当前已经完成计算的脉冲，只影响下一次发射。

光粒运行中的布局变化只能在安全逻辑批次边界生效，不改变已经完成的传播历史。

# 5. 发射器

## 5.1 固定规则

- 主发射器是关卡固定对象；
- 玩家不能移动发射器；
- 发射器只允许四方向：上、右、下、左；
- 方向配置在开始运行后锁定；
- 发射器通过统一发射请求描述当前位置、方向和光形态；
- 发射器不直接执行传播。

## 5.2 视觉

同一种光形态使用一张基础朝向图片，通过旋转视觉子节点显示四个方向。

- 不旋转发射器逻辑根节点；
- 光线发射器和光粒发射器使用不同外观；
- 切换光形态时切换对应视觉；
- 方向和光形态是逻辑事实，图片不能反向决定玩法状态。

## 5.3 光形态切换

关卡可决定：

- 固定使用光线；
- 固定使用光粒；
- 允许玩家在布置阶段切换；
- 通过形态转换器在传播过程中改变。

开始运行后，主发射器初始光形态锁定。形态转换器仍可按照自身规则处理传播中的光。

# 6. 光线

- 支持八方向传播；
- 主发射器只从四个正交方向发射；
- 镜面等机关可以把光线反射到八方向；
- 按当前稳定布局同步计算完整路径；
- 路径默认显示约 1 秒；
- 路径视觉消失不代表普通独立水晶熄灭；
- 下一次发射重新读取当前布局；
- 使用最大步数、重复状态或最大状态数防止无限循环；
- 颜色只属于光线。

颜色完整版本保留：

- 白；
- 红；
- 绿；
- 蓝。

滤光规则完整版本保留：

- 白光经过滤光片变为对应单色；
- 同色光保持；
- 异色光被吸收；
- 不制作 RGB 混色。

- 不回溯已经完成的事件；
- 颜色系统不作用于光粒。

# 8. 机关栏与拖拽

每关分别配置：

- 机关种类；
- 每种机关总数；
- 是否可由玩家放置；
- 是否允许在运行期移动；
- 占用格；
- 可放置区域规则。

拖拽流程：

```text
按住左键拿取
→ 显示预览
→ 自动吸附逻辑格
→ 合法性反馈
→ 松手二次校验
→ 成功提交或完整回滚
```

规则：

- 预览不等于正式占用；
- 未成功放置前不扣库存；
- 非法放置不改变库存与占用；
- 已放置机关移动失败必须回原格；
- 拖回机关栏是回收；
- UI 区域不得点击穿透；
- 多格机关使用锚点格和占用偏移；
- 占用更新必须原子提交或回滚。

# 10. 水晶与通关

## 10.1 基础独立水晶

- 合法命中后点亮；
- 光线路径消失或光粒离开后仍保持；
- 只在 R 或关卡重置时恢复；
- 未点亮与点亮必须有清晰视觉差异。

## 10.2 完整复合条件

后续完整版本保留可组合条件：

- 所需光形态；
- 所需光线颜色；
- 是否属于组；
- 组 ID；
- 顺序编号；
- 完成窗口；
- 是否为必需目标。

启用的条件之间使用“并且”。

## 10.3 同时组和顺序组

完整设计保留：

- 第一颗合法成员点亮时启动固定窗口；
- 后续触发不刷新窗口；
- 窗口内完成后整组保持到 R；
- 窗口到期未完成则整组清除；
- 顺序错误或同一逻辑时刻触发多个不同序号时清除进度。

## 10.4 通关

所有本关必需目标满足后：

- 进入 `COMPLETED`；
- 冻结拿取、放置、移动、回收、配置和发射；
- 显示通关结果；
- 允许 R 或进入后续流程。

# 13. 重置

R 是完整运行重置，不只是清光路。

至少恢复：

- 取消拖拽和预览；
- 清理当前光执行；
- 使旧异步回调失效；
- 清光路或光粒；
- 重置目标；
- 清除完成状态；
- 清理玩家机关和动态占用；
- 恢复库存；
- 清零运行期移动次数；
- 恢复发射器初始配置和光形态；
- 返回 `SETUP`；
- 重新要求点击“开始运行”。

关卡预置对象、静态地图和初始配置不得被误删。
