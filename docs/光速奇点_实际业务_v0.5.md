# 《光速奇点》实际业务

> 版本：v0.5  
> 状态：内部更新稿  
> 项目成员：陈俊贤、潘陈俣、张梓涵  
> 目标平台：Windows 10/11 x86_64

## 1. 项目概述

《光速奇点》是一款以光学解谜为核心玩法、以中国科学家宣传与科学知识传播为内容目标的单机游戏。玩家先在网格中布置机关，发射后机关配置被锁定，但仍可移动自己放置的可移动机关，从而在光传播期间动态改变光路。

项目希望先保证游戏本身具有完整、清楚、可持续游玩的解谜体验，再以戴琼海院士等中国科学家为主要宣讲对象，通过游戏中的成就解锁、右下角弹窗和主界面的成就展示页面，向玩家介绍科学家的经历、成果与科研精神。

项目当前以小团队首次完整开发为前提，不追求商业化规模，不考虑平台上架、联网、多人、排行榜和创意工坊等功能。

## 2. 项目目标

### 2.1 产品目标

完成一个可以在 Windows 10/11 上独立运行的游戏版本，具备：

- 完整的开始、选关、关卡、通关、重置和退出流程；
- 可理解、可重复游玩的光学解谜玩法；
- 布置阶段与发射后受限移动相结合的动态解谜闭环；
- 可移动墙体消除器及可消除墙机制；
- 一组经过设计和测试的正式关卡；
- 中国科学家宣传和科学知识传播内容；
- 清楚的资料来源、资源来源和已知问题说明。

### 2.2 宣传目标

通过游戏内容，重点围绕戴琼海院士等中国科学家，让玩家：

- 了解戴琼海院士等中国科学家的姓名、研究方向和代表性成果；
- 理解科学研究与现实工程、社会发展之间的联系；
- 感受到科学探索中的长期积累、困难和个人选择；
- 对中国科学史和相关人物产生继续了解的兴趣。

宣传内容不能只是把科学家姓名贴在关卡标题上，也不能为了配合玩法随意改写科学事实。

### 2.3 游戏目标

游戏应当首先作为一款解谜游戏成立：

- 玩家能理解基本规则；
- 相同布局、输入和操作时序应得到稳定、可预测的结果；
- 发射后允许的移动操作与被锁定的配置必须有明确反馈；
- 关卡应有逐步教学和难度递进；
- 失败时给予可观察反馈，但不直接公布解法；
- 科学家内容不应频繁打断玩家操作。

## 3. 目标用户

当前暂定的主要用户包括：

- 对轻量解谜游戏感兴趣的普通玩家；
- 中学生和大学生；
- 对科学史、中国科学家或光学知识感兴趣的人；
- 学校项目评审、展示和体验人员。

目标用户尚未最终收窄。后续业务讨论需要确认主要服务对象，以决定：

- 文本难度；
- 科学知识深度；
- 科学家资料长度；
- 关卡难度；
- 是否需要术语解释；
- 整体游戏时长。

## 4. 产品定位

### 4.1 产品形式

- 类型：单机网格解谜游戏；
- 视觉风格：8bit/像素化低成本科幻风格；
- 目标平台：Windows 10/11；
- 操作方式：键盘和鼠标；
- 游戏结构：光粒章节、光线章节、混合章节；
- 核心操作结构：布置机关、开始发射、运行中受限移动、停止或结算、重新调整；
- 内容结构：玩法关卡与科学家宣传内容相互配合，但不强制完全绑定。

### 4.2 当前不包含的内容

本阶段暂不考虑：

- 游戏平台上架；
- 手机端适配；
- 联网功能；
- 多人合作或对战；
- 排行榜；
- 创意工坊；
- 宣传 PPT；
- 宣传视频；
- 预告片；
- 专门制作的演示版本；
- 高成本剧情演出。

## 5. 科学家内容的定位

科学家宣讲以戴琼海院士等中国科学家为主要对象。具体科学家名单、人物数量和每位人物对应的内容仍需后续确认。

科学家内容的主要呈现方式不是长篇关卡说明，而是玩家在游戏过程中达成特定条件时获得成就。成就以类似 Steam 的方式从画面右下角弹出，在不打断操作的情况下展示科学家姓名、成就名称和科研精神关键词。主界面同时提供“成就展示”入口，供玩家集中查看已经获得和尚未获得的成就。

### 5.1 成就弹窗

成就弹窗建议包含：

- 成就图标；
- 成就名称；
- 对应科学家姓名；
- 一句简短的科研精神说明；
- “已解锁科学家档案”提示。

弹窗应当：

- 从右下角出现；
- 停留数秒后自动收起；
- 不暂停游戏；
- 不遮挡核心操作区域；
- 同时触发多个成就时排队显示；
- 玩家关闭或错过后仍可在档案页面查看。

### 5.2 成就展示页面

主界面新增“成就展示”入口。

玩家可以在该页面查看：

- 已解锁成就；
- 尚未解锁成就；
- 成就图标与名称；
- 对应科学家；
- 科研成果或科研精神简介；
- 成就获得条件；
- 可选的首次解锁时间；
- 资料来源或扩展阅读信息。

未解锁成就可以只显示轮廓、名称或隐藏说明，避免提前泄露关卡解法。

成就弹窗负责在游玩中即时提醒，成就展示页面负责玩家之后集中回顾和阅读。

### 5.3 成就触发方式

成就应由玩家在正常游玩中自然获得，例如：

- 第一次完成某种光路；
- 第一次使用新机关解决问题；
- 完成某个章节；
- 在同一次运行中完成特定组合目标；
- 完成具有代表性的关卡挑战。

成就不能要求与核心玩法无关的重复刷取，也不应成为主线关卡解锁的强制条件。

### 5.4 科研精神表达

成就主要用来体现科学家的科研精神，例如求真、坚持、创新、协作、面向实际问题和长期积累。

具体精神表述必须建立在可靠人物资料之上，不能先设计口号，再强行套到科学家身上，也不能使用无法确认出处的名言。

### 5.5 科学家档案

成就弹出后，可同步解锁对应科学家档案。档案作为完整内容的承载位置，可包含：

- 基本信息；
- 研究领域；
- 代表成果；
- 重要经历；
- 科研精神；
- 可靠资料来源。

成就弹窗负责短暂提醒，科学家档案负责完整阅读。

### 5.6 辅助呈现

章节标题、关卡名称、背景图和简短提示可以辅助科学家宣讲，但不作为主要方式。避免每关开始和结束都出现长篇文字，影响解谜节奏。

## 6. 科学内容要求

所有科学家资料和科学知识应满足：

- 使用可靠来源；
- 不编造人物经历；
- 不夸大个人贡献；
- 不把多人或团队成果错误归于单一人物；
- 区分历史事实、普及解释和游戏化表达；
- 对有争议或来源不一致的内容进行说明；
- 记录引用资料的名称和出处。

科学知识可以适当简化，但不能通过错误内容来迁就玩法。

## 7. 业务范围

### 7.1 必须完成

- 可独立运行的 Windows 游戏；
- 完整核心流程；
- 正式可玩的关卡；
- 发射后机关配置锁定和运行期机关移动；
- 墙体消除器与可消除墙；
- 以戴琼海院士等科学家为主要对象的宣传内容；
- 游戏内成就系统及右下角弹窗；
- 主界面的成就展示页面；
- 科学家档案或同等完整内容页面；
- 资料来源记录；
- 外部素材授权记录；
- README 和已知问题说明。

### 7.2 有时间再做

- 更完整的科学家收藏系统；
- 关卡评价；
- 更多隐藏成就或挑战成就；
- 章节过渡；
- 更丰富的声音和动画；
- 更完整的术语解释。

### 7.3 暂不做

- 商业化运营；
- 用户账号；
- 云存档；
- 在线更新；
- 社区内容；
- 复杂剧情；
- 大规模科学家数据库。

## 8. 业务交付物

最终业务交付建议包括：

1. Windows 10/11 可运行游戏包；
2. 完整 Godot 源项目；
3. 正式关卡内容；
4. 科学家主题成就内容；
5. 游戏内右下角 Steam 式成就弹窗；
6. 主界面的成就展示页面；
7. 科学家与科学知识来源记录；
8. 外部美术、字体和音频授权记录；
9. 游戏使用说明；
10. 已知问题清单；
11. 实际业务、玩法、开发规范兼技术栈和项目管理文档。

## 9. 业务验收建议

业务验收至少应检查：

- 游戏能否完整运行；
- 玩家是否能理解产品主题；
- 科学家内容是否真实、清楚并注明来源；
- 科学内容是否与游戏整体风格协调；
- 成就是否能在不打断游戏的情况下体现戴琼海院士等科学家的成果与科研精神；
- 主界面的成就展示入口是否明显，页面是否便于集中回顾和阅读；
- 科学家宣传是否只是装饰；
- 是否存在明显事实错误；
- 游戏是否有完整关卡和结算流程；
- 运行期间移动机关后，光粒和光线是否按照统一规则更新；
- 墙体消除器移走后，原墙体是否可靠恢复；
- 玩家是否能清楚区分“可移动位置”和“不可修改配置”；
- 最终版本是否符合目标平台要求。
