# 2. Godot 4.6.1 Standard

## 用途

- 2D场景；
- TileMapLayer；
- Inspector配置；
- Resource数据；
- Signal；
- Timer；
- 输入；
- Windows导出；
- 编辑器工具脚本。

## 采用原因

- 团队当前环境统一；
- 适合小型2D网格游戏；
- 节点和场景利于拆分机关；
- Inspector适合张梓涵配置关卡；
- GDScript迭代速度快；
- MCP可辅助读取、运行和验证。

## 限制

- `.tscn` 多人同时修改容易冲突；
- `@tool` 脚本必须防止编辑器副作用；
- AI可能生成旧版本API；
- 不当使用节点查找会形成强耦合；
- 逻辑确定性需要项目自行设计。

# 3. 静态类型 GDScript

## 用途

- 核心控制器；
- 传播模块；
- 机关；
- 关卡对象；
- UI；
- 诊断；
- 存档。

## 采用原因

- 与Godot集成直接；
- 团队学习成本较低；
- 静态类型能减少AI生成代码的隐式错误；
- 场景脚本和Resource脚本统一；
- 无需引入.NET导出环境。

本项目不采用C#混合开发。

# 4. 网格与地图

## 4.1 `Vector2i`

负责：

- 光的位置；
- 方向；
- 下一格；
- 镜面映射；
- 固定对象Cell；
- 占用格；
- 多格偏移；
- 地图边界。

## 4.2 `GridMetrics`

唯一保存：

- `CELL_SIZE = 64`；
- `HALF_CELL_SIZE = 32`；
- 单格世界尺寸。

不保存地图内容和关卡状态。

## 4.3 `TileMapLayer`

负责：

- 地面；
- 墙体；
- 合法区域；
- 禁止区域；
- 地图形状；
- 装饰；
- Tile自定义数据。

推荐层：

```text
TerrainLayer
WallLayer
LegalAreaLayer
DecorationLayer
```

## 4.4 `GridPlacedObject`

负责编辑器固定对象：

- Cell；
- 世界位置同步；
- 拖动后吸附；
- 占用偏移；
- 编辑器校验。

# 5. 公共架构技术

## 5.1 统一发射请求 `EmissionRequest`

用途：

- 将发射器当前配置封装成稳定数据；
- 隔离发射器和具体传播实现；
- 为光线、光粒和未来形态提供同一入口。

最小字段：

- 来源ID；
- 起始Cell；
- 方向；
- 光形态；
- 执行ID；
- 后续需要时加入颜色。

## 5.2 光形态 `LightForm`

用途：

- 标记当前请求是光线还是光粒；
- 只描述类型，不执行传播。

当前：

```text
RAY
PARTICLE
```

## 5.3 光运行协调器 `LightRuntimeCoordinator`

用途：

- 接收发射请求；
- 根据光形态选择已注册执行模块；
- 统一发出开始、交互、完成和失败；
- 处理取消；
- 隔离核心循环和具体模块。

## 5.4 世界查询 `LightWorldQuery`

用途：

- 给传播模块提供只读关卡查询；
- 隔离传播算法和TileMapLayer、注册表、占用表、目标节点。

提供：

- 是否在地图内；
- 是否阻挡；
- 当前格有哪些交互对象；
- 当前格有哪些目标；
- 某光形态是否可通过。

## 5.5 统一交互事件

传播模块输出事件，不直接修改具体水晶或机关。事件可包含：

- 执行ID；
- Cell；
- 进入方向；
- 光形态；
- 颜色；
- 到达Tick；
- 来源ID。

# 6. 光线技术

## 模型

- 同步或队列式完整路径计算；
- 八方向；
- 最大传播步数；
- 分支队列；
- 重复状态保护；
- 逻辑结果与视觉分离；
- 路径显示约1秒。

## 当前复用基础

现有普通光线算法、墙体阻挡、镜面查询、水晶命中、最大步数和路径视觉应迁移到 `gameplay/light/ray/`，不重新从零实现。

## 后续扩展

- 分光；
- RGB单色；
- 滤光片；
- 特殊持续光线；
- 多束同Tick目标事件。

---

# 7. 光粒技术

## 模型

- 光粒实体状态；
- 整数Tick；
- 到达事件队列；
- 三档速度；
- 非回溯；
- 安全批次移动；
- 稳定判定；
- 无永久轨迹。

## 建议状态

- 粒子ID；
- Cell；
- 方向；
- 速度；
- 下一到达Tick；
- 是否活动；
- 来源ID。

光粒不复用光线完整路径算法，只复用发射请求、世界查询、交互事件和统一执行结果。

# 8. 占用、放置和库存

## 8.1 `OccupancyRegistry`

双向索引：

```text
Cell → Mechanism ID
Mechanism ID → Occupied Cells
```

负责原子占用事实和一致性检查。

## 8.2 放置事务

通过独立控制器处理：

- 预览；
- 合法性；
- 提交；
- 回滚；
- 运行期移动扣次。

## 8.3 库存资源

完整版本使用：

- `PlaceableItemDefinition`；
- `LevelInventoryEntry`；
- `LevelInventoryController`；
- `InventorySlotView`。

当前单槽代码可作为迁移起点。

# 10. 诊断技术

## 10.1 日志

- 内存缓冲；
- 按需落盘；
- 日志等级；
- 模块标签；
- 执行ID；
- 轮转；
- 删除最旧文件。

## 10.2 状态快照

使用JSON输出到：

```text
user://diagnostics/snapshots/
```

通过各模块公开快照接口收集，不读取私有字段。

## 10.3 自检

- 模块内部不变量；
- 跨模块SelfCheckRunner；
- 启动检查；
- 按命令检查；
- Debug构建断言。

## 10.4 游戏内Debug控制台

仅Debug构建启用，支持：

```text
log
check
state
clearlog
```
